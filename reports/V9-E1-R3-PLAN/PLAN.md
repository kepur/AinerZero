## 2. 核心诊断：⑥ 的残差几乎被投影掉了

- **实现**：⑥ 训练与预测时，把一步残差投影到 ∂F_prior/∂φ 列空间的正交补上（`arms_net.project_onto_orthogonal_complement`）。
  - 这里的 J 对 **全部 5 个参数** 求导：friction、restitution、mass、linear_damping、angular_damping（`jacobian.PARAM_NAMES`）；取下一帧的位置和速度，共 6 维。
  - ⑤ 和 ⑥ 实际只辨识 **friction 与 restitution**（`arms_nonnet.IdentifyArm` 的默认 target_params）。而且只在前缀信息足够的子空间里辨识，其余方向保持 φ₀。
- **后果**：mass 和两个阻尼方向既没辨识，也不许残差修正，两边都不管。
  - 线阻尼一列的方向就是沿速度方向。S 族缺的二次空气阻力 −c|v|v 也沿速度方向，几乎落在这一列里，所以被投影整个去掉。这解释了 S 族 bounce_collision 和 ramp_roll 上，⑥ 与 ① 一样带着阻力偏差（0.0114 对 0.0111，0.0061 对 0.0063）。
  - 恢复系数只有在前缀里出现过反弹时才辨识得出；没出现时停在 φ₀，残差在这个方向上也被投影掉，可能就是 occlusion_pass 多报接触的来源。
- **实测**（训练集，每族每场景 4 集）：投影去掉了速度维残差能量的 81%–100%。

| 场景 | P | S |
|---|---|---|
| bounce_collision | 80.8% | 81.8% |
| box_stack | 95.4% | 98.2% |
| occlusion_pass | 88.5% | 93.0% |
| ramp_roll | 83.7% | 88.7% |
| table_slide | 100.0% | 100.0% |

- **另一现象**：位置维的残差在投影后反而大了几十到上百倍。原因是投影在位置与速度混合的 6 维欧氏空间里做，单位不同；位置残差原本很小，被混进来的分量放大了。绝对量仍小，r3 不改它，列在 §9。
- **与设计意图的偏差**：r4 草案 §2 写的是「残差只在辨识之后学，并投影到 ∂F_prior/∂φ 的正交补上」，用意是不让残差去抢辨识已经解释的部分，好让 φ̂ 保持可解释。把没辨识的方向也投影掉，超出了这个用意：⑥ 的残差在结构上学不到 S 族缺的机制，H-S 在 r2 里因此不可检验。这是实现层面的缺陷，不是 ⑥ 这个设计本身被证伪。

## 3. r3 的臂 ⑥′

⑥′ 与 ⑥ 只有一处不同：**投影只去掉本集辨识出的方向。**

- J_id = J · V_id。V_id 是 ⑤ 子空间辨识在本集、本物体上给出的已辨识参数方向，也就是加权 Fisher 特征值 ≥ 1e-3 的方向（r4 §8 第 3 条），落在 friction/restitution 的平面里。
- 残差投影到 J_id 列空间的正交补上；SVD 截断仍为 1e-6·σ_max。
- 本集没有辨识出任何方向时，V_id 为空，残差不投影。
- 训练目标与预测必须走同一个投影函数，由测试锁定。
- 其余照旧：网络结构、参数量、标准化、零初始化、早停、学习率、batch、64000 步上限、种子 42/43/44、验证集划分、数据。

## 9. 不在 r3 里做、留作以后的方向

- **辨识阻尼和质量**：⑤ 只辨识 friction 与 restitution。若把 damping 也纳入辨识，它就该从 ⑥′ 的残差中让出，两者要一起设计。
- **按单位加权的投影**：§2 提到的位置维放大问题。可以改在网络目标的标准化坐标里投影。
- **多步训练**：③⑥ 的一步监督与 10 步评测错配。先验是 numpy 实现，不可微，需要先定梯度怎么穿过先验。

## 10. 风险与局限

- **看过 dev 再改方法**：⑥′ 是看了 r2 dev 之后提出的。缓解有三点：
  - 修改有独立的机制依据（§2 的实测与设计意图），不是按 dev 分数调出来的；
  - 只改一处，门规则逐字不变；
  - dev 只用一次决定是否放行，final 从未读过。
- **⑥′ 不一定修好 P 族 F1**：多报接触的来源若不是恢复系数（§5 第 1 步会查），F1 可能仍低于 ②，r3 就在 dev 停下。
- **赢家诅咒**：dev 上过线的幅度可能在 final 回落。所以除门的结论外，final 的点估计与区间也要一起报。
- **结论范围**：只适用于这五类场景和这两族世界。

## 11. 2026-11-06 补充：批准后的核查推翻了 ⑥′ 的前提，建议不按本方案运行

用户批准后、动代码之前，一级在训练集上做了只读核查（scratchpad `r3diag/ident_prefix.py`，每族每场景抽 6 集）。

| 场景 | 辨识出的方向数 k（4 帧 / 10 帧） | k = 0 的占比 |
|---|---|---|
| bounce_collision、box_stack、occlusion_pass、ramp_roll | 0 / 0 | 两族都是 100% |
| table_slide | 1 / 1（摩擦方向） | 0% |

- 恢复系数、质量与阻尼在任何场景都辨识不出。table_slide 上辨识出的摩擦与真值相差 0.37–0.44，比 φ₀ 离真值还远。它是补偿先验结构偏差的等效参数（r4 §4 第 5 条已说明 φ̂ 不是物理真值）。
- **推论**：k = 0 时，⑥′ 不做投影，φ̂ = φ₀，训练目标就是 s_{t+1} − F_prior(s_t; φ₀)，与 ③ 逐字相同。所以 5 类场景中有 4 类，⑥′ 就是 ③，只在 table_slide 上不同。
  - 按 ③ 的 dev 分场景数估算，⑥′ 的 P 族 e_10 约 0.033，门槛要求 ≤ 0.0264，预计不过。
- **反过来看 ⑥**：它在 dev 上表现好，主要是因为投影抹掉了 81%–100% 的残差，残差几乎不起作用，就避开了 ③ 那种添乱。这不能说明残差学到了缺失的机制。
- **又一处实现不一致**：⑥ 训练时只用每集前 4 帧辨识（`build_training_windows` 用的是网络窗口长度 HISTORY_K = 4），评测时用 10 帧前缀。按上表，它只影响 table_slide 上 φ̂ 的取值。
- **结论**：本方案 §3 的 ⑥′ 预计会失败，不值得用掉已批准的 7680 s。一级建议撤回，在用户重新决定之前不写代码、不放卡、不运行。

## 核对方法

`pose_audit.py` 只读、不改源码，用真值做事后比对：

- 主地图坐标系和真值只差一个平移（指南针朝向是绝对的），平移量取前缀第一帧；
- 每次 `_advance` 之后，只要不在迷路状态，就比对主地图位姿和真值；
- 回合结束时，比对主地图上的已知格与真值格、事件记忆与真值动力学；
- 回合和臂的种子与 `evaluate_tasks` 一致。插桩后的成功率与探索段完全相同：analytic 0.639，hybrid 0.792，说明插桩没有改变行为。

## 合并修复：在探索留出图上比较

数据：m2，种子 0，探索留出图 7_900_000 起的 30 张。

| 版本 | analytic 长目标 | hybrid 长目标 | 并图次数 / 其中错的（analytic） | 并图次数 / 其中错的（hybrid） | 错误位姿步数（analytic / hybrid） |
|---|---|---|---|---|---|
| 原版（`m2-s0`） | 0.639 | 0.792 | 101 / 42 | 109 / 48 | 876 / 901 |
| 只修 F-02（`m2-s0-f02`，地图变了） | 0.603 | 0.838 | 46 / 18 | 62 / 23 | — |
| 修 F-02，并图门槛 0、6、12 | 0.544 | 0.838 | 36 / 18 | 46 / 18 | 306 / 357 |
| 修 F-02，并图门槛 16 到 30 | 0.603 | 0.838 | 36 / 0 | 32–34 / 0 | 30 / 65 |

**解读**

- 并错的偏移，重叠都只有 12–15 格，而且全部一致：一面直墙平移一下仍然对得上。门槛 16 以上就一次也不错。
- 门槛取 20，落在安全区间 16–30 的中间。
- 长目标成功率不变。说明现在的瓶颈不是并错图，而是迷路时间长：约 1.1–1.7 万个迷路步，约占总步数的五分之一。

**交叉检验**（门槛 20）

- 换一套没用过的探索留出图（`m2-s1-e7950000-k*`，种子 1，7_950_000 起的 30 张）：门槛 12 和 20 都没有错误并图，成功率相同（analytic 0.642，hybrid 0.821）。
- m1（`m1-s0-e7900000-k20`）：两臂长目标都是 1.0，没有错误位姿。

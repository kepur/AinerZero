# S3 第三阶段设计稿 r0：跨回合记忆的分层、晋升与回滚

一级 claude（主责），2026-11-10。用户 11-10 选定方向「跨回合记忆」。依据：`ARCHITECTURE_V9.md` §1 记忆等级、§3 `SpatialMemory`、§5 S3 过门条件；第二阶段 `reports/V9-S3-PHASE2/FINAL-REPORT.md`；本目录 `tier1-explore/` 的摸底。**待非作者复核。**

## 0. 为什么做，做什么

架构对 S3 的过门要求是四条：历史读回、旧技能保留（式 6）、晋升必须有独立测试、回滚可复现。前两条由第一、二阶段完成，后两条和跨回合记忆还没碰过，第二阶段的情景库每回合清空。

架构里的三个等级：

| 等级 | 架构定义 | 本阶段的实现 |
|---|---|---|
| FAST | 当前信念与工作状态 | 当前回合的情景记录，即第一、二阶段的情景库 |
| MID | 情景库与待验证假设 | 往回合的驻留观察，以及按地点聚成、尚未晋升的条目 |
| SLOW | 通过独立测试、版本晋升的规律 | 由两个不同回合确认过的条目，带版本链，可回滚 |

**这一版是机制验证，只有一个问题的答案事先不确定。**

| 问题 | 性质 |
|---|---|
| Q1：把往回合的记录直接并进检索池，会不会伤害回合内读回（M2 记忆干扰诊断） | **经验问题**。朴素做法确实可能出问题，幅度事先不知道 |
| Q2：跨回合记忆能否回答回合内记忆答不了的问题 | 由结构决定，作基础门 |
| Q3：要求独立回合确认的晋升，在稳定的固定格上是否好过「最近一次」 | 方向由登记的扰动率决定，幅度受里程计漂移影响 |
| Q4：回滚能否在固定格改变后恢复，代价多大；回滚能否逐位复现 | 恢复由结构决定；代价必须报告；复现是契约 |

**不训练，纯 CPU，不导入 MLX。** 读出是「取检索到的记录在中心格看到的 token」。第二阶段已经说明，训练出的读出头准确率贴着检索上限（A2 0.845，第一名能看到答案 0.862）。本阶段研究的是记忆管理，不重测读出技能。因此本阶段**不支持任何关于学习组件的能力结论**。

## 1. 摸底（`s3p3x-explore`，不作结论）

脚本 `tier1-explore/explore.py`、`explore2.py`，结果在同目录的 `results*.json`。专用命名空间 `s3p3x-explore`，以后登记的分区一律用别的名字。阈值和规则都在这个命名空间上定，探针、dev、final 上不再调。

| 发现 | 数字 |
|---|---|
| 跨回合位姿误差：同一格在不同回合的估计位姿之差 | 中位 3 格，90% 分位 7 格，≤ 1 格的只有 20% |
| 回合内读回（长间隔、已换），完美读出 | 只查当前回合 0.694，并进往回合记录 0.528，**掉 0.166**。6 组参数下掉 0.17–0.19 |
| 固定格被诱饵遮盖、且固定格没有改变（「稳定」） | 照抄当前 0、最近一次 0.639、门控 0.734、门控不回滚 0.730 |
| 固定格改变后的到达 | 照抄当前 0.697、最近一次 0.549、门控 0.423、门控不回滚 0.086 |
| 门控查到的已晋升条目在正确格子上的比例 | 97.6% |
| 用真值格子代替估计位姿来认地方（只作诊断） | 门控在稳定诱饵事件上约 0.79，估计位姿 0.734 |

遮盖率敏感性（门控减最近一次）：

| 遮盖率 | 稳定诱饵事件的收益 | 固定格改变后的代价 |
|---|---|---|
| 0.1 | +0.057 | 0.188 |
| 0.3（登记值） | +0.095 | 0.126 |
| 0.5 | +0.107 | 0.084 |

门控在稳定的固定格上总有收益，在改变的固定格上总有代价，两者的比例由扰动率决定。**所以 Q3 的结论只在登记的扰动率下成立，代价和收益一起报告。**

## 2. 世界与事件

世界、观察、巡游、里程计都沿用第一、二阶段的冻结代码（`s2.world`、`s3.world`、`s3.tour`、`s3.store`、`s3.cues`），只新增一个内容层和回合序列。

**世界序列（新模块 `s3/persist.py`）：** 每个世界连续 12 个回合，每回合 360 步。

| 内容 | 规则 |
|---|---|
| 固定格 | 每个世界 4 个，位置和 token 由世界种子一次定下，回合内不换 |
| 诱饵 | 每回合每个固定格独立以 0.3 的概率整回合显示另一个 token（≠ 当前固定值） |
| 换代 | 第 6 回合起（0 起数），每个固定格独立以 0.5 的概率永久换成另一个 token |
| 易变格 | 每回合 4 个，位置和 token 每回合重抽，回合内在第 130–220 步换 token，同第一阶段 |
| token | 固定格和易变格都取 F1 族的 8 个 token。不能凭 token 本身分辨是不是固定格 |

所有内容格一起打乱后交给冻结的 `run_tour`，第一个作起点。起点位姿按第一阶段的做法真值锚定，这是跨回合能对齐的前提，见 §9。

**事件：**

| 事件 | 定义 | 答案 |
|---|---|---|
| 回合内读回 | 冻结的 `extract_readout_events`，长间隔（≥ 80 步）且已换。只出现在易变格上 | 上次到达时的 token |
| 固定格查询 | 第 e ≥ 1 回合里第一次到达某固定格的那一步 | 该格当前的固定值 |

固定格查询按两个维度分类。

| | 当前显示的 token |
|---|---|
| **诱饵** | ≠ 答案，必须靠记忆 |
| **干净** | = 答案，照抄当前就对 |

| | 时期与格子 |
|---|---|
| **稳定** | 换代前，或换代后没被改的格子 |
| **已改** | 换代后被改的格子 |

查询的时刻和分类用真值定义，同第一、二阶段的读回事件。各策略只用学生可见的量：估计位姿、地形、token。

## 3. 记忆与策略

**驻留观察：** 每个回合结束后，把每段「站在同一估计位姿、中心格有 token」的连续记录收成一条观察（取第一步）。

**认地方：** 沿用第二阶段的手工线索打分 `相似度 × 49 × λ − 位姿距离`，λ = 1.0。另外要求位姿距离 ≤ 5、3×3 世界朝向地形完全一致，取分最高的一条。阈值在摸底命名空间上定。

**条目（新模块 `s3/promotion.py`）：**
- 每条新观察先匹配已有条目，匹配不上就新建条目，锚点是这条观察的位姿和地形。
- 每个条目每回合只记一票：这个回合里它收到的观察中最常见的 token。

**晋升规则 R2：**

| 条目状态 | 规则 |
|---|---|
| 未晋升 | 某个 token 累计 ≥ 2 票（来自两个不同回合）就晋升。并列时取票多的，再取最近的 |
| 已晋升 k | 在 k 最近一票**之后**，另一个 token k′ 累计 ≥ 2 票，就回滚 k、晋升 k′ |

晋升证据永远来自写入它以外的回合，这就是本阶段的「独立测试」。只有回合结束时才更新，查询只用之前回合的记忆。

**版本：**
- 每次回合结束，SLOW 内容如果变了，就生成一个新版本：`{父版本哈希, 回合, 排序后的 (条目, token)}`，哈希取 SHA-256。
- 版本快照落盘。查询使用回合开始时的版本。

**策略：**

| 代号 | 策略 | 固定格查询怎么答 | 回合内读回怎么答 |
|---|---|---|---|
| C | 无跨回合记忆 | 照抄当前 | 只查当前回合（FAST） |
| L | 写穿：最近一次 | 最近一次匹配到的往回合观察；没有就照抄 | — |
| G | 分层，门控晋升加回滚（**架构方案**） | 分最高的已晋升条目；没有就退回 L | 只查当前回合（FAST） |
| G-NR | 门控、不回滚 | 同 G，但晋升后不再改 | — |
| U | 统一检索池 | — | 当前回合可用记录加该世界所有往回合记录一起排序 |
| G-T、L-T | 诊断：用真值格子认地方 | 同 G、L | — |

**检索细节：**
- 回合内读回沿用第二阶段 A2 的手工线索：只查当前回合时，候选是 `t ≤ 查询 − 5` 的记录。
- U 的打平按全局时间（回合 × 360 + 步）取最近，所以当前回合的记录优先。
- 实现直接用冻结的 `cues` 打分函数，测试核对它在只查当前回合时与 `cues.rank_candidates` 的第一名逐条相同。

## 4. 假设与门

| 假设 | 比较 | 事件 | 判据 | 性质 |
|---|---|---|---|---|
| **H1（基础门）** | G − C | 全部诱饵 | ≥ 0.10，下界 > 0 | 由结构决定，不作发现宣称 |
| **H2（干扰）** | C − U | 回合内读回 | ≥ 0.05，下界 > 0 | **经验问题**。过了说明往回合记录不能直接并进同一个池子 |
| **H3（独立确认）** | G − L | 稳定诱饵 | ≥ 0.05，下界 > 0 | 方向由扰动率决定 |
| **H4（回滚）** | G − G-NR | 已改格子上的全部查询（干净和诱饵） | ≥ 0.10，下界 > 0 | 由结构决定 |

**登记的代价（必须报告，不设门）：**
- L − G 在已改格子上，即门控的可塑性代价，摸底是 0.126；
- C − G 在干净事件上；
- 固定格从首次被看到到晋升要经过几个回合；
- 落在非固定格上的已晋升条目数（误晋升）；
- 同一固定格被认成多个条目的次数。

**统计：** 按世界配对 bootstrap，10000 次，种子 20261110。同一世界的所有回合一起进出，因为同一世界里的事件跨回合相关。

**合法性门（失败则整个实验无效）：**

| 门 | 判据 | 抓什么 |
|---|---|---|
| 事件标签 | C 在诱饵事件上恰好 0，在干净事件上恰好 1 | 事件分类写错 |
| 分层路由 | G 的回合内读回预测与 C 逐条相同 | 路由接错 |
| 版本可复现 | 每个查询从它所用版本的快照独立重算，预测相同；整个序列重跑两遍，版本哈希链相同；把存储恢复到任一历史版本，重答当时的查询，结果相同 | 回滚不可复现 |
| 最小样本 | final：回合内读回 ≥ 2000，稳定诱饵 ≥ 800，已改格子 ≥ 1000；dev 和探针减半 | 样本不够 |

`claims` 只有整体有效时才可能为真。

**常设报告（缺项判运行不完整）：**
- 每个回合序号上的曲线；
- G-T、L-T 与 G、L 的差，即认地方的误差；
- 条目数和版本数；
- 跨回合位姿误差分布；
- 用时、峰值内存。

M2 零状态对照不适用：没有学习模型，**不可比，阻断相应的能力结论**（架构 §5 常设对照的规则）。H2 本身就是 M2 记忆干扰诊断，即写入新记忆、不更新参数时旧读回的变化。

## 5. 分区与用量

**命名空间：**

| 命名空间 | 用途 |
|---|---|
| `s3p3-probe` | 100 世界，冻结前用正式运行器跑，只用来确认设计 |
| `s3p3-dev` | 100 世界，至多 2 次，账本写用途 |
| `s3p3-final` | 200 世界，冻结后才生成，只读一次，批准行写进预登记 |
| `s3p3-train` | 本阶段没有训练，只占位，满足四个分区互不相同的守卫 |

- 测试一律用替身分区，并有测试防止回退。
- 种子测试核对新命名空间与 `s3p1-*`、`s3p2-*`、`s3p2b-*`、`s3p3x-explore` 不相交。

**只有 final 能支持结论。** dev 是彩排；除非合法性门失败或运行器出错，否则不因 dev 改设计。

## 6. 运行器

`reports/V9-S3-PHASE3/run_phase3.py`，复用第二阶段冻结的 `run_guard.py`，不改它。

启动顺序同第二阶段：拿锁 → `python -I`、字节码新鲜、清单与已加载模块、第三方版本、git 干净 → 分区 → 请求参数 → 运行目录与报告 → 记账。结束时再核对一次清单和已加载模块，不一致就判无效。

虽然不用 MLX，仍然持 `artifacts/locks/m0-worker.lock`，和 MLX 运行串行，避免抢 CPU 时被墙钟上限误判。

**落盘：**
- 每个事件的各策略预测、答案、分类、世界号、回合号，存为 `.npz`；
- 每个世界的版本链和快照存为 JSON；
- 所有文件的 SHA 写进报告，供独立复算。

第二阶段运行器的守卫清单（记忆 `runner-guard-checklist`）逐条适用。

## 7. 预算

本机 CPU，不付费，不用 GPU。摸底：100 世界 × 12 回合，生成加分析约 50 秒。

| 运行 | 预计 | 硬上限 |
|---|---|---|
| 探针、dev | 约 1 分钟 | 30 分钟 |
| final | 约 2 分钟 | 30 分钟 |

## 9. 这一版不回答

| 不回答的问题 | 原因 |
|---|---|
| 学习组件 | 学习检索在跨回合池子上会怎样、参数化的 SLOW（巩固进权重、按版本晋升）都没测 |
| 无锚定的重定位 | 每回合起点位姿真值锚定，跨回合对齐因此只受回合内漂移影响。真实智能体要靠地形重新定位，这属于 S1 |
| 容量受限的情景库 | 每个世界约 44 个条目，容量不是瓶颈，需要另设任务 |
| 教师写入 | 没有教师通道，「教师不能直接写 SLOW」留给 S6 |
| Titans 式记忆 | 不在本阶段 |
| 多次换代 | 换代只有一次，只测这一种回滚 |

## 10. 风险

- **Q2–Q4 接近由结构决定。** 通过不算发现，价值在机制和证据链；只有 H2 的幅度事先不确定。
- **扰动率是我定的。** Q3 只在登记的扰动率下成立，敏感性见 §1，代价必须和收益一起报告。
- **读出是符号的。** 它不是模型能力，只是记忆管理的读出。
- **复核者与作者同模型。** 盲点可能相关。

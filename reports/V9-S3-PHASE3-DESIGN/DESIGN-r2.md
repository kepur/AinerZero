## 0. 定位

**这一版是机制与契约验证，不检验科学假设。** 在「符号读出、不训练」的范围里，结果基本可以预先算出：复核者另起的命名空间 `s3p3x-rv1109` 上所有判断都与摸底相同。所以这一版：
- 不设「通过即发现」的门；
- 登记的是**契约门**（§4），机制必须满足，否则实现有错；
- 另登记**描述量**（§4），带区间，在 final 上跑一次，不走 dev。

架构对 S3 的过门要求有四条：
- 历史读回：第一、二阶段已做；
- 旧技能保留（式 6）：第二阶段只对 A2 成立，学习检索臂 A3H 在同样容量下没有满足 0.05；
- 晋升必须有独立测试证据：本版用契约门做实；
- 回滚可复现：本版用契约门做实。

读出取检索到的记录**中心格**的 token，对应第二阶段的「严格命中」（0.642），不是「能看到答案」（0.862）。训练出的读出头能从整个视野读答案，所以本版的干扰幅度只对严格读出成立。本版**不支持任何关于学习组件的能力结论**。真正值得做实验的学习问题见 §9，另起设计。

## 3. 记忆、规则与策略

**驻留：** 估计位姿或中心格 token 变了，就开始一段新驻留；中心格没有 token 的一步结束当前驻留。每段驻留在第一步收成一条观察，同第一、二阶段的估计位姿和世界朝向地形。

**认地方：**
- 打分是第二阶段的手工线索 `相似度 × 49 × λ − 位姿距离`，λ = 1.0；
- 门槛是位姿距离 ≤ 5、3×3 地形完全一致；
- 取分最高的一个，**并列取编号最小（最早建立）的条目**；
- 条目的锚点在建立时固定，之后不更新。

**每回合一票：** 取这一回合进入该条目的观察里最常见的 token，**并列取这一回合最先观察到的**。

**规则 R2：**

| 条目状态 | 规则 |
|---|---|
| 未晋升 | 某个 token 累计 ≥ 2 票就晋升；并列取票多的，再取最近的 |
| 已晋升 k | k 最近一票之后，另一个 token 累计 ≥ 2 票，就**替换**成它 |

R2 的含义：至少两个不同回合给出同一个 token，后一个回合检验前一个回合的候选。两票里可以有一票来自建条目的那个回合。

**两种「回滚」：**
- **条目级替换**：R2 第二条，由 D4 测；
- **版本级恢复**：把 SLOW 存储恢复到任一历史版本，由 K2、K3 测。

**版本记录：** 每次回合结束后 SLOW 的 token 集合如果变了，就记一个版本。

```
{父哈希, 回合, 已晋升条目: [[编号, token, 锚点位姿, 锚点地形, 投票 [[回合, token], …]], …]}
```

哈希是去掉哈希字段后、按键排序的紧凑 ASCII JSON 的 SHA-256。查询使用回合开始时的版本。

**策略：**

| 代号 | 固定格查询 | 回合内读回 |
|---|---|---|
| C | 照抄当前 | 只查当前回合（第二阶段 A2 的手工线索，`t ≤ 查询 − 5`） |
| L | 往回合观察中最近一次过门槛的；没有就照抄 | — |
| G | 分最高的**已晋升**条目；没有就退回 L | 同 C（按查询类型路由） |
| G-NR | 同 G，晋升后永不替换 | — |
| MODE | 分最高的条目（不论是否晋升）全部投票的众数，并列取最近；没有条目就退回 L | — |
| G-perm | G 的答案经过每个世界一个固定的 token 置换 | — |
| G-SR | 当前回合 `t ≤ 查询 − 5` 的记录里有过门槛的，就取其中分最高的 token（同分取最近）；否则同 G | 同左 |
| U(α) | — | 当前回合可用记录加往回合全部记录，分数减 α × 回合差，同分按全局时间取最近 |
| GT、LT | 诊断：用真值格子认地方的 G、L | — |

G-perm 的置换种子 `derive_seed(ns, "perm", w)`，`random.Random(种子).sample(F1, 8)`。

## 4. 契约门与描述量

**契约门（任一不满足，整个运行无效）。** 信任链：生成器 →（K2b）落盘日志 →（K2）版本与答案 →（K6）描述量读的事件。

| 门 | 判据 | 能证明什么 |
|---|---|---|
| K1 版本内容 | 每个版本含 §3 的全部字段；父链完整；哈希可重算；从版本记录重答的 SLOW 与运行内的存储相同 | 版本记录自洽 |
| K2 独立复核 | `verify_worlds.py` 只用标准库，不导入项目代码，在另一个进程里读盘上的 `worlds.jsonl`。(a) 重算每个版本的哈希、核对父链；(b) 晋升证据：每个已晋升条目的 token 至少 2 票，一回合一票、按回合递增、不晚于版本所在回合；相对父版本换了 token 的，新 token 在旧 token 最后一票之后至少 2 票；锚点不变；已晋升的条目不消失；(c) **从观察日志独立重建条目、投票和 R2，重建出的版本链与记录逐个哈希相同**；(d) 每个查询用的是该回合开始时生效的版本，用它和观察日志独立重答，与记录的 G、L 相同；(e) 世界数等于登记数，查询数等于 `events.npz` 里的固定格查询数 | 给定这份观察日志，机制按规格运行 |
| K2b 生成器一致 | `verify_generation.py` 在另一个进程里只导入世界生成器（`persist` 及第一阶段冻结模块，不导入 `promotion`、`analysis_p3`、`cues`），按种子重新生成，独立重算驻留观察、固定格查询（时刻、位姿、地形、显示、答案、诱饵、已改）、回合内读回事件、世界种子与布局哈希，与日志逐条相同；世界按 0…n−1；三类计数与 `events.npz` 相同 | 日志本身没有被改写，把 K2 的起点钉回生成器 |
| K3 恢复与重放 | 从每个回合结束的完整状态恢复，重放后面的回合，**全部状态**（含未晋升条目的投票）和版本链与原来相同 | 契约测试：`state()`、`restore()` 没有漏掉影响决策的字段。现实现上的决策只依赖序列化字段，所以这道门主要防回归 |
| K4 事件标签 | 诱饵 ⇔ 显示 ≠ 答案；稳定事件的答案等于回合 0 的固定值；已改事件的答案等于换代值且 ≠ 回合 0 的值；查询步等于逐步重算的真值首次到达 | 换代前的稳定事件按构造恒真，换代后的稳定格才是真检查 |
| K5 样本数 | 三类事件数在预期的 ±7%（回合内读回）、±13%（稳定诱饵）、±21%（已改格子）以内。预期每 100 个世界 2030、800、1070（摸底与复核命名空间的均值）。带宽是「事件数 − 预期」的 4 倍标准差，同时计入 final 的波动和预期数自身的估计误差，每世界标准差取自复核者的 `k5_band.json` | 只抓大比例的丢失或重复；小比例由 K2b 与 K6 逐条抓 |
| K6 事件与日志一致 | `events.npz` 里每个固定格查询的世界、回合、步、答案、显示、诱饵、已改、G、L，每个回合内读回的世界、回合、步、答案，都与 `worlds.jsonl` 逐条相同；世界集合一致 | 描述量读的就是被 K2、K2b 核对过的那份数据 |

负测试：
- 单字段篡改哈希、父链、条目、投票、锚点、观察、答案或查询所用版本，K2 必须报错；
- 会重算哈希的一致篡改（改版本、改证据、删条目），K2 必须报错；
- 一致改写观察日志后用同一规则重建版本并重答，K2 抓不到，K2b 必须报错；
- 改动、删除或调换查询与回合内读回事件，K2b、K6 必须报错。

**其余描述臂**（C、MODE、G-perm、G-SR、U(α)、G-NR、GT、LT 和 D8 的计数）不在 K2 里重算。它们由单元测试在测试世界上与独立写法逐条比对，最后由非作者独立复算。

**描述量**（全部登记，按世界配对 bootstrap，10000 次，种子 20261110，95% 区间，另报 Bonferroni 口径；不设通过与否）：

| 编号 | 内容 | 事件 |
|---|---|---|
| D1 | G − G-perm；G − C | 诱饵；另报全部固定格查询 |
| D2 | C − U(α)，α ∈ {0, 0.5, 1, 2}；U(0) 被往回合记录抢走的比例 | 第 1 回合起的回合内读回 |
| D3 | L、MODE、G、G-NR 的准确率；G − L、G − MODE、MODE − L | 稳定诱饵 |
| D4 | G − G-NR、G − L、G − MODE；按回合的恢复曲线；G 第一次超过 C 的回合 | 已改格子 |
| D5 | G-SR − G；G-SR 走 FAST 的比例 | 全部固定格查询；回合内读回 |
| D6 | 起点平移误差 k ∈ {1, 2, 3, 5}：D2（α = 0）、D3 的 G − L、D4 的 G − G-NR | 同上 |
| D7 | GT − G、LT − L | 稳定诱饵、已改格子（各两项） |
| D8 | 条目数、版本数；误晋升；同一固定格的多个已晋升条目；混格条目比例；写入与查询时认地方并列的频率；投票并列的频率 | — |
| D9 | C − G | 干净事件 |

D6 的平移量：每个世界、回合、k 一个种子 `derive_seed(ns, "offset", w, e, k)`，`random.Random(种子)` 依次取 `randint(−k, k)` 作 dx、dy，加到这一回合所有估计位姿上。等价于起点平移误差，朝向不变。

**记忆的生命周期：** 每个世界的记忆在运行内建立，用完就丢，不写进任何会被复用的存储。落盘的版本和观察日志只作证据（架构 `SpatialMemory`：「final 分区经历不可写」）。

## 6. 运行器

`reports/V9-S3-PHASE3/run_phase3.py`，复用冻结的 `run_guard.py`。

- 启动顺序和结束时的核对同 r0 §6。
- smoke、probe 必须带 `--use-id`。
- smoke 只读替身 `s3p3x-smoke`；probe、final 先过 `check_stage_namespace`。
- 每次运行都记录代码清单哈希，即运行器传递闭包加两个校验脚本，不含设计稿，并记录这些文件在工作区里是否干净。
- `make_prereg.py` 只接受这样的探针：有效、在 `s3p3-probe` 上跑出、工作区干净，并且代码清单哈希等于要冻结的代码。
- 主运行（k = 0）做全部检查，落盘 `events.npz` 和 `worlds.jsonl`；锚定误差 4 档各落一个 `events_k{k}.npz`。
- 然后用 `python -I` 在子进程里先后运行 `verify_worlds.py`（K2）和 `verify_generation.py`（K2b）。两个子进程的超时都取本次运行剩余的时间，超时按触及时限处理。
- 两个校验脚本都在冻结清单里。

## 7. 预算

本机 CPU，不付费。final 200 世界：主运行加 4 档锚定误差约 4 分钟，K2 几秒，K2b 重新生成约 1.5 分钟，预计 10 分钟以内，硬上限 30 分钟。

## 5. 新发现（r2 引入或未闭合的问题）

### R1（必改，实现层）：C7 的 φ 后验承载与现有 belief Mapping 形状冲突

**r2 原文（§3 C7, line 177）**：「在线参数信念 `p(φ|D)` 作为键 `"physics_param_belief"` 挂在 `UpdateScheduler.update(belief=...)` 已有的通用 `Mapping` 上」。

**冲突证据（全部来自本地源码，只读）**：
1. `interfaces/scheduler.py:42`：`update(self, belief: Mapping, dirty: Sequence)` —— 签名确实是通用 Mapping，**类型上允许**任何键。
2. `fakes/scheduler.py:132-144`：**全量回退路径**（闭包超 `f_max`，正常会发生）先 `nodes = tuple(belief.keys())`，再 `for node in nodes: updated[node] = belief[node] + 1`。`ParamBelief` 是结构体，`+ 1` 直接 `TypeError`。
3. `interfaces/scheduler.py:66-76`：`require_graph` 要求每个值都是**邻居序列**（`list/tuple/set/frozenset`），`ParamBelief` 值进 belief graph 会被 `SignalRejected`。
4. `interfaces/types.py:277`：`BeliefSummary.belief: PoseBelief`（frozen dataclass，`types.py:184`），**不是 Mapping**——所以这个键也无法经 `BeliefSummary` 进出，只能在「调用方临时构造的 Mapping」里存在，而仓内目前没有生产实现定义该 Mapping。
5. `tests/v9/contracts/test_scheduler_contract.py:23-24`：合同测试把 belief 固定为 `{"bn-1": 0, "bn-2": 0, "bn-3": 0}`（节点→数值），即现行语义是「节点→数值」。

**后果**：B12 实现卡拿到 C7 后，要么改 fake 的算术路径（C7 允许改 `fakes/`，但这会把 belief Mapping 的语义从「节点→数值」变成「节点→数值 + 旁挂元数据」，属于**未声明的接口语义变更**，正是 A12 的 M6 想避免的），要么另找载体（那就等于 C7 没定）。两条路都会在 G7 第一次跑全量回退时暴露。

**建议改法（二选一，任一句即可）**：
- (a) 在 C7 补一句：「该键是**旁挂元数据**，不参与 `dirty_set` 闭包、不参与数值更新；`update` 的全量回退只对 `bn-` 前缀节点做算术」，并在 C7 里按 M7 方案 (a) 的方式**显式声明这是一次 belief Mapping 语义变更**（附回滚）；
- (b) 不挂在 belief Mapping 上，改为 `UpdateResult` 的附加字段或独立 `ParamBeliefStore`，并写明「不改 `BeliefSummary`、不改 `RunStore`」。

### R2（必改，记录准确性）：§8 M1 行的「删」与归属都不实

- r2:214 写「已改写 §2 D3 开头并在 RESEARCH_LOG 补勘误（不改已封存 REPORT 原字节）：**删**『方向相反』」。实测：r1 **从未写过**该判断（r1 全文 `OSVerify`=0、`FNR`=0、`方向相反`=0；r1:76 原文只有「『单侧』指只控制错误接受……误拒只报告，不作门」）。所以不是「删」，是 r2 **新增**了该措辞（作为勘误引述）。
- r2:89 括号内「**r1 草案与 REPORT** 写『方向相反』系事实错误」——REPORT 成立（`REPORT.md:61`），**r1 不成立**。

### N1（建议）：K 的「最大独立子集」缺选择算法

r2:59 末句「K 计数只对满足该谓词的最大独立子集计」。谓词本身可判定，但「最大独立子集」的求取没有算法（一般图上是 NP-hard），K 仍可能被实现者按不同启发式算出不同值。建议补「按世界实例分组取最大组，或按时间序贪心取极大独立集」这类可复现规则。

### N2（建议）：「E_pers ≥ 1/α_t（或等价 p ≤ α_t）」不严格等价

r2:96 括号里的等价只在 e-value 恰由 `1/p` 构造时成立；任意有效 e-value 与 p-value 之间没有这个双向等价。建议删「或等价」，或改为「若同时报告 p 值，则 `p ≤ α_t` 是充分条件之一」。

### N3（建议）：M1 的「可补采证据重测」与 D3-3 的记账关系未声明

r2:89 用「候选仍留在 MID、后续可补采证据重测」论证误拒可恢复；但 r2:65 的 `N_max` 是冻结的候选预算、r2:92 的 `α_t` 是按检验次序发的。**重测同一候选算不算新的 t、要不要消耗新的 `α_t`、`R_{t−1}` 怎么计**——不写清，B12/G7 会各自解释，且这直接决定 M1 的「可恢复」是不是真的可恢复（若重测受 `N_max` 限制，可恢复性就是有界的）。建议在 D3-3 补一句。

### N4（建议）：4a 窗口如何排除出 D_valid 标定未定义

r2:48 说 4a 上下文「不进入 D_valid 标定」，但 D3-4（r2:117）把 D_valid 定义为 `(D ∪ C)` 的覆盖包络 ∩ C 上的残差分位数。既然 4a 窗口要从 C 的分位数计算里剔除，就需要一条可执行规则（例如「先跑一遍 MSG 标 4a，再把命中的窗口从 C 的次序统计量样本中剔除」）。建议补一句，否则 NIS 下尾的污染只是被口头挡住。

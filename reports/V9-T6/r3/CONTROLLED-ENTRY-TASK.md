# T6 真实模型入口的最小 CPU 工程任务

依据：用户 AGENTS 要求所有真实模型工作复用既有 CLI、共享锁、中央 RunStore 和预算/资源守卫。T6 params v1 已登记单次 1200s、RSS 8GiB、最多64视图，允许 Small/Base；此卡只补 CPU 工程，不执行模型、不写生产台账、不扩这些上限。

在既有 `ainerzero` CLI 增加清楚区分 T4/T6 的 DA3 受控分支。不得借用 T4 1800s/600s 账或修改原 T4 冻结模型/审批。T6 使用中央教师 RunStore 的独立 T6 身份/总预留，保守累计上限收紧到1200s，不重置旧预留；同次派生作业共享64视图额度。审批/输入/源码 SHA/权重 identity/方法与统计协议均必须先冻结绑定。若统计协议没有登记，inspect 报明确缺项，run拒绝；不替统筹编写“已批准”。

inspect 必须零模型导入/零锁/零生产台账写入。run 必须在任何模型 import/加载之前完成全部授权检查、独占既有 m0-worker.lock、中央 RunStore 的不可退还预留、既有资源/电源/交换空间门；父进程实际监督整个自有子进程组，墙钟与8GiB RSS越界立即停止自有组并保存原失败，不停止用户服务。持锁覆盖模型卸载，失败与未知占用保持红，不自动再跑。无模型/CPU fallback/no-op适配器成功冒称DA3。

单一受控调用进入本卡已有 `envs/teachers/t6/pipeline.py`；权重外层 strict 加载及候选输出规则保持。真实执行模型/标定仍在T6，入口卡只交CPU工程候选。

CPU测试只用显式隔离替身：RunStore仅唯一临时库，锁仅唯一临时路径；不导入Torch/MLX、不读写生产ledger。实际子进程验证拒绝顺序、双进程锁互斥、失败/超时组清空、并发总预算不能超订、8GiB/64views守卫、重入不退款、错manifest/错审批/未知model拒绝；真实非零退出、完整原始stdout/stderr与SHA。至少四组完整源码单区域变异对照，区分模型测试替身与实际模型运行。

报告保留环境与审批缺项，交独立非作者复核；不部署、不提交推送、不得在此卡启动DA3/MPS/MLX/Blender。

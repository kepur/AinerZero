## 0. 北极星

1. **产品**：把 AinerHub 的小说和剧本自动做成**人物始终一致**的日漫短剧。
   - 画面用线条渲染，可以换风格、换色调、出多语言版本；
   - 每秒画面的成本以秒计算，不用视频扩散模型逐帧重画。
2. **研究**：同一个确定性世界，给 AinerZero 提供带真值、可封存、难度可控的时间、空间和语义经验。先用来考它；经批准后，才用来训练它。
3. **平台**：同时用满 M 系列芯片的 CPU、GPU、神经引擎、媒体引擎，以及大统一内存和大 SSD。数学定义和数据格式不绑定 MLX，给 CUDA 留路。

**第一版的优先级不变**：先做出可重复渲染的 30 秒、480p、24 FPS 黑白线条动画（Gate A），再做有独立评测的轻量世界学习。**训练跑完不等于学会了理解世界。**

## 1. 原则

沿用 v1.0 第 0 节的八条，新增四条：

9. **人物身份是硬约束**：身份由不可变的角色资产和参数锁定（ACIS）。任何网络只能在允许的范围内修饰外观，不能重新决定这个人物长什么样。
10. **一次模拟，多次取景**：世界只模拟一次。镜头、剪辑、风格、语言版本都只是对同一份状态日志的不同读法。换风格不用重跑世界；换语言只改台词时间线，再按新时间线重跑同一个确定性内核。
11. **确定性优先于逼真**：能用解析式就不用数值积分，能用事件驱动就不用随机粒子，能用规则就不用学习。
12. **数据有出身**：渲染出来的数据一律标为「外部派生」（`external_derived`），带完整的来源、许可和辅助类型，默认不进任何训练准入（D-001 第 4 条）。

## 3. World Kernel（权威真值）

**ADR-0003**：真值在 Python 内核里，Godot 只按状态日志回放渲染。
- **理由**：
  - 规则全是解析式的（云按风积分、波纹公式、root motion 行走、解析碰撞），Python 可以逐字节重放，没有 GPU 依赖，也绕开了 Godot 物理和 GPU 粒子的复现风险；
  - W0、W1 和 AinerZero 的评测包只需要状态，不需要渲染，可以在 CPU 上多进程批量生成，和 GPU 训练同时跑。
- **Jolt 的位置**（D-001 第 2 条）：项目的 3D 物理引擎选 Jolt，但只用于「仅视觉」的次级运动（例如道具晃动），不写入真值，也不进入观察。人物移动和碰撞全部用解析方式处理。
- **将来要交互或做 VR 时**：把内核移植成 GDExtension，并用 Python 生成的黄金日志做逐 tick 一致性测试（另开 ADR）。

### 3.1 时间（ADR-0004）

- `sim_hz = 120`。tick `k` 对应 `t = k / 120` 秒。规范 v1.0 写的 60Hz 和 24fps 不能整除（每帧 2.5 个 tick），会造成半 tick 采样。120Hz 能被 24、30、60 帧每秒和一拍二的 12 帧每秒整除。
- 三个时钟：
  - `tick`：整数，唯一的权威时间；
  - `world_time`：环境时间，按时间线分段线性映射 `world_time = w0 + rate·(t − t0)`。太阳、云、风用它，可以和镜头时间不同速；
  - `shot_time`：剪辑时间。剪辑决策表（EDL）把每个输出帧映射到 `(camera_id, tick)`。同一段动作可以用多个机位覆盖，世界只算一次；慢动作和停格也只是改变 `shot_time → tick` 的映射。
- 输出帧 `n`（24fps）默认取 tick `5n`。角色层按一拍二时取 `10·⌊n/2⌋`，见第 5 节。

### 3.2 随机数

- 计数式、和调用顺序无关：`u = hash64(episode_seed, entity_id, subsystem_id, tick, draw_index)`，`uniform = (u >> 11) · 2⁻⁵³`。哈希用 SplitMix64 链，具体定义和测试向量由 T02 固定在 `contracts/rng.md`。
- 禁止使用全局 RNG。Godot 侧不产生任何会影响真值的随机数。

### 3.3 规则（R1 范围）

- **行走**：
  - 路径是折线或样条，按弧长参数化：`s(t)` 由步态的加速、匀速、减速段闭式给出，位置为 `p(t) = path(s(t))`；
  - 朝向沿切线，转向角速度有上限，用闭式平滑；
  - 步态相位 `φ(t) = ∫ cadence dt`，`cadence = speed / stride_length`，所以脚不会打滑；
  - 脚着地事件是 `φ` 穿过动画剪辑元数据里的着地相位时触发的。剪辑元数据由资产流水线导出（`clip.json`：根运动曲线、步长、着地相位）。
- **碰撞**：人物是竖直胶囊，在 XZ 平面上看是圆；静态障碍是凸多边形或圆。R1 在编译期就检查路径与障碍、人物与人物之间是否相交（两个移动圆的首次接触时间用二次方程闭式求解），相交就判场景无效并报错，不做物理求解。
- **云**：`p(t) = p0 + ∫ wind(world_time) dt`，形状用确定性噪声，参数是种子。
- **波纹**：`h(x,t) = Σ_i A_i e^{−λ(t−t_i)} sin(k_i r − ω_i (t−t_i))`，其中 `r = |x − x_i|`，只在 `t ≥ t_i` 且 `r ≤ c·(t − t_i)`（波前以内）时生效。v1.0 原式没有波前条件，会让涟漪瞬间出现在整个水面。
- **水花**：由 `footstep_water` 事件触发，参数（粒子数、初速度、寿命）全部从计数 RNG 取，轨迹用抛物线闭式表示。不用 GPU 粒子。
- **倒影**：只在渲染侧做（平面反射），不属于真值。

### 3.4 状态日志与快照

- 状态日志按 tick 写 JSONL（或 Parquet）：实体的位置、速度、朝向、动画剪辑和相位、接触标志、可见性，以及当 tick 的事件。私有字段和公开字段分文件存放（第 9 节）。
- 由于各子系统都可以闭式求值，`state(t)` 能在任意时刻直接算出。快照（每 120 tick 一次）只用来做校验和快速定位，不是重放的必要条件。将来加入有内部状态的积分器（如弹簧骨骼）时，快照就成为必需。
- 状态哈希：浮点数先量化到 1e-6 米、1e-6 弧度，再按规范 JSON 计算 SHA-256。同一台机器上要求逐字节一致；跨机器按容差比较，同时记录设备信息。

## 4. 渲染（Godot 4.7.2）

- **运行方式（T01 必须先实测）**：Godot 的 `--headless` 用的是假渲染器，通常无法截图或录像。在 macOS 上要用窗口模式（可以很小或放在屏幕外）配合 Movie Maker（`--write-movie`，固定帧率），或者用 SubViewport 回读。还要实测窗口被遮挡或最小化时会不会降频。
- **渲染后端**：Forward+，走 Metal（T01 确认）。M2 没有硬件光线追踪，所以不用实时全局光照和屏幕空间反射。
- **WorldPlayer**：每个输出帧，按 EDL 取得 `(camera_id, tick)`，再从状态日志设置各实体的变换、`AnimationPlayer.seek(phase)`、表情和口型权重、相机参数。Godot 不跑 `_physics_process` 去改真值。
- **输出通道**（多个 SubViewport 共用同一个世界和相机）：
  - `line_alpha`（R8，只有线条）、`color`（toon）、`depth`（16 位线性深度）、`normal`（视空间）、`object_id`（16 位，对象编号映射表放在私有一侧）；
  - 运动矢量推迟到 R2。
- **抗锯齿与确定性（ADR-0007）**：禁用 TAA 和一切时序累积效果，因为它们让帧依赖历史，破坏任意时刻跳转。改用 2 倍超采样渲染（1708×960）后下采样到 854×480。线条宽度按屏幕像素定义，所以下采样时同步换算。
- **录制**：先输出无损 PNG 序列，再用 VideoToolbox 硬件编码成 MP4（h264/hevc）。图像回放按容差比较（逐像素差 ≤ 1 级、PSNR），状态和事件要求逐字节一致。

## 5. 线条、风格与「一拍二」

- **轮廓线**：
  - 背面外扩描边，沿平滑法线外扩（法线存在 UV2 或顶点色里，避免硬边法线断开）；
  - 在裁剪空间按 `width_px · 2 / viewport_h · w` 外扩，得到恒定的像素宽度；
  - 用逐顶点宽度系数（顶点色通道）控制收尖；按距离给宽度设上下限。
- **结构线**：五官、发束、衣褶用显式的几何条带或贴图线（「3D 头上的 2D 脸」）。深度、法线不连续形成的边缘只作补充，不会全部变成墨线。
- **toon 明暗**：2～3 个色阶。阴影色按调色板槽单独指定（日漫的阴影要偏色相，不是单纯变暗），见 ACIS。
- **风格包**（`contracts/style_package.v1.schema.json`，R2）：包含线宽、收尖、线色、色阶、各调色板槽的阴影色、色调 LUT（白天/黄昏/夜晚的色彩脚本）、纸纹和颗粒、分层节拍。换风格只是换参数，不需要训练。
- **一拍二、一拍三**：按图层设置节拍：
  - 相机常用一拍一；
  - 角色身体、脸常用一拍二；
  - 特效可以一拍一，也可以一拍二。

  节拍在时间采样层实现，即角色层取 `10·⌊n/2⌋` 的状态，不改真值。
- **LTX 精修（可选）**：`line_alpha`、`depth`、姿态通道可以作为 LTX 2.5 IC-LoRA 的控制视频（ai-studio 网关已支持），只给少数重点镜头用。默认成片不经过扩散模型。

## 6. 人物身份系统（ACIS）

详见 [ACIS.md](ACIS.md)。要点：
- **身份不可变、状态可变**；
- **调色板锁定**，ColorNet 和风格包只能在材质允许的范围内调整明暗与反光；
- **视角形变**是相机相对头部角度的纯函数，只作用于渲染网格；
- **脸部细节按 480p 分级**，按脸的像素高度决定画多少细节；
- **身份校验**：
  - 转身回归图；
  - 调色板 ΔE；
  - 已知顶点的关键点投影；
  - 用本机已有的 CCIP（`deepghs/ccip_onnx`）检查跨场景一致性。

R1 只交付身份包 v0：自制低模、骨骼、调色板，以及身份包的哈希。

## 7. 台词、配音、口型

详见 [PERFORMANCE.md](PERFORMANCE.md)。要点：
- **生成链路**：TTS（本机 IndexTTS 2.5）→ 强制对齐 → 映射成日漫的 5 种口型 → 一拍二驱动口型形变。口型是场景的一部分，不需要额外的扩散对口型，成本只有几秒；
- **时间线跟着配音伸缩**：每种语言有自己的时长，靠停格来吸收差异；
- **声音身份**属于 ACIS（每个角色、每种语言各一套声音档案）。

## 8. 小说翻译系统对接

详见 [NOVEL_TO_WORLD.md](NOVEL_TO_WORLD.md)。
- **复用协议**：直接吃 AinerHub 已有的 `ainer.scene/v1`（Director Core，引擎无关，Y 轴向上、单位米、右手系、yaw 为 0 时面向 +Z）。
- **缺口**：协议里没有台词、表情、语言版本和风格引用，需要在 AinerHub 另开任务，扩展成 v1.1。在那之前，AWZ 用独立的「表演轨」文件补上。
- **不执行 LLM 写的代码**：LLM 只产出数据（场景 JSON）。Godot 和 Blender 都不执行 LLM 写的代码（和 Director Core 的规则一致）。

## 9. 数据与来源

### 9.1 episode v1

- **结构**：`contracts/episode.v1.schema.json`，由 T05 实现。一个 episode 是一个目录：
  - `episode.json`（头信息）；
  - `frames.jsonl`（逐帧公开记录）；
  - `private/`（真值，只有评测方读取）；
  - `line/`、`depth/` 等二进制通道；
  - `manifest.json`（每个文件的大小和 SHA-256）。

  不把整个 episode 塞进一个巨大的 JSON。
- **来源字段**：
  - `origin` 固定为 `external_derived`（D-001 第 4 条）；
  - `actor` 填 `{kind: system|baseline, actor_id, policy_revision}`；
  - `assistance` 是枚举数组，取值和 AinerZero 的 `AssistanceKind` 一致：`demonstration`、`curriculum`、`label`、`rule`、`unknown`（D-001 第 5 条）；
  - `license` 只能是 `self_generated` 或 `cc0`（D-001 第 3 条）。
- **分区**：`train`、`development`、`final`、`quarantine`（D-001 第 7 条，与 AinerZero 统一）。切分的单位是「世界」，即种子、布局、资产、规则参数区间和策略的组合。`final` 封存后只评一次。
- **隔离规则**（满足任一条就进 `quarantine`）：
  - 来源、操作者或策略未知；
  - 辅助类型为 `unknown`；
  - 许可不在白名单里；
  - 哈希不符；
  - 帧缺失或 tick 不连续；
  - 公开字段里出现私有字段；
  - 同一个世界出现在多个分区。

### 9.2 观察档位

| 档位 | 内容 |
|---|---|
| A `objects_public_v1` | 允许观察的对象状态 |
| B `line128_v1` | 128×128 线稿 + 动作历史 |
| C `line_depth_v1` | 再加深度（单独的消融组，成绩不和 B 混写） |

`object_id`、身份编号、私有状态，永远不进入纯线稿档位。

### 9.3 存储

- 线稿帧用 1 位打包（128² 一帧 2KB），按分片存成二进制，另配 Parquet 索引，并用 zstd 压缩；
- 深度存 16 位 PNG；
- 不可变数据集放在 `datasets/`，任何时候都不进 git。

## 10. 世界学习（W0–W3）

沿用 v1.0 第 3 节，调整三点：
1. **数据生成走 CPU 道**：W0、W1 只需要内核状态，在 CPU 上多进程生成，和 GPU 训练同时跑（第 12 节）。
2. **AWZ 的 W1、W2 定位为「有监督参照模型」**：给出强基线和上限。发育式学习者只放在 AinerZero（它的 M6 已经规划了 CNN 加 8 个 slots），两个仓库不在同一份考题上重复造学习者。
3. **增加「历史需求」标注**：每个预测样本标注「只看当前观察能否答对」，用来区分模型是否真的用上了历史。这正是 AinerZero 目前卡住的地方，见 [AINERZERO_BRIDGE.md](AINERZERO_BRIDGE.md)。

## 11. AinerZero

详见 [AINERZERO_BRIDGE.md](AINERZERO_BRIDGE.md)。
- **三步走**：E-0 只导出评测包 → E-1 AinerZero 只评测（它那边另开任务）→ E-2 经用户批准后才训练。
- **契约扩展**：帧区域引用、想象分支的核对引用、多时钟，以后在 AinerZero 另开任务登记（D-001 第 9 条）。本仓库不修改 AinerZero。

## 12. 充分利用 Apple Silicon

| 资源 | 用途 | 规则 |
|---|---|---|
| CPU（M2 Max 12 核） | 世界内核、批量生成 episode、打包和压缩、W0 评测 | 用多进程；内核是纯函数，天然可并行 |
| GPU（Metal） | Godot 渲染、MLX 训练和推理 | 全力跑；轻量任务并行，重型任务（LTX 这类）全机串行（ADR-0009） |
| 神经引擎 | Apple 语音转写与词级时间、Vision、转成 Core ML 的小模型（如 CCIP） | 和 GPU 工作同时跑 |
| 媒体引擎 | VideoToolbox 编码 MP4、ProRes 母版 | 不占 CPU 和 GPU |
| 统一内存 96GB | 热数据集常驻内存（1 位线稿 1000 万帧约 20GB）；用 memmap 读分片 | 系统保留 16GB；可用内存低于 16GB 就停下并归档 |
| SSD | 不可变分片、顺序写、memmap 随机读 | 剩余空间不低于 50GB |

- **MLX**：
  - 训练步骤用 `mx.compile`，用 bf16；
  - 用 `vmap` 做批量展开；
  - 消息传递的瓶颈在需要时用 `mx.fast.metal_kernel`；
  - 先跑 100 步和 500 步基准，再估总时长。
- **给 CUDA 留路**：
  - 模型数学有 PyTorch 参考实现，并附测试向量；
  - 权重用 safetensors；数据格式与框架无关；
  - 内核是纯 Python/NumPy；
  - Godot 在 Linux 上可以走 Vulkan，将来能做渲染农场。

## 13. 运行治理

- **角色**：Claude 和 Codex 是平级统筹，负责架构、算法、参数、ADR 和验收；其他模型是执行者和独立验证者。规则见 [COORDINATION.md](../COORDINATION.md)。
- **GPU（ADR-0009 全力跑，取代 ADR-0006 第 1–3 条和 D-001 第 6 条）**：
  - 不等空闲，直接全力跑；
  - 轻量 GPU 任务（Godot 渲染、小模型）随时并行；
  - 重型任务（LTX、扩散、大模型）全机串行，包括 ai-studio 网关上的 LTX 任务，由 AinerRelay 的闸门处理；
  - AinerZero 有实验在跑时不再挡 AWZ；
  - AWZ 从不持有 AinerZero 的锁；AWZ 自己的重任务仍用 `tools/locks/awz-heavy.lock` 互斥。
- **训练状态机**：`DRAFT → DATA_VALIDATED → BASELINE_MEASURED → TRAINING → EVALUATING → {REJECTED | REVIEW_REQUIRED} →（人工批准）PROMOTED`。不自动晋升。
- **每次运行记录**：配置哈希、git commit、数据清单、种子、设备、参数量、曲线、时长、峰值内存、检查点哈希。出现 NaN、内存压力、swap 激增或超出预算时，停下并记录，不无限重试。

## 16. 风险与注意事项

1. **Godot 无头模式不能渲染**：T01 先测清楚窗口模式加 Movie Maker 是否稳定、被遮挡时会不会降频。
2. **步长和帧率**：60Hz 和 24fps 不能整除，已改为 120Hz（ADR-0004）。
3. **时序效果**：TAA、运动模糊累积、屏幕空间时序滤波都会破坏任意时刻跳转，全部关闭（ADR-0007）。
4. **资产导入的确定性**：
   - 锁定 Blender 导出器版本（本机 5.2.2）和 Godot 导入设置；
   - `.import` 文件进 git，`.godot/` 不进；
   - 每个资产记录 SHA。
5. **3D 不等于日漫**：脸部要靠技巧（平滑法线或 SDF 脸部阴影、视角相关的鼻线、2D 眼睛）。要达到《转生史莱姆》那样的效果，需要美术迭代；自制低模只是占位。
6. **480p 下线条闪烁**：细几何在低分辨率下会闪。用宽度上下限、超采样和脸部细节分级来压，并量化闪烁指标。
7. **许可**：白名单只有自产和 CC0，字体、贴图、天空盒、音效同样适用。下载任何 CC0 资源都要用户同意。
8. **身份和语言版本**：身份与语言无关。如果某个地区要改人设，那就是新的身份版本，不是改参数。
9. **跨硬件**：同一台机器要求逐字节一致；跨机器按容差。性能数字一律写实测，并注明是 M2 Max。
10. **泄漏**：`object_id`、身份编号、私有状态都属于特权信号，只能出现在明确标注的消融组。
11. **GPU 争用**：AinerZero 的限时实验在 10-13 两次因 Metal 争用超时。所有重任务都要走 GPU 锁，不在别人跑实验时启动。
12. **范围**：v1.0 第 13 节的非目标不变（大型视频扩散、流体、实时光追、VR 双眼渲染都不进 MVP）。

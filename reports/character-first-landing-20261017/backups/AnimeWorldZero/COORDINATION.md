## 三类角色

| 责任 | 统筹（Claude / Codex） | 执行者 | 验证者 |
|---|---|---|---|
| 路线与架构 | 定目标、门槛、ADR | 指出实现风险 | — |
| 算法与参数 | 选候选、事先登记参数和预算 | 按登记值实现，报告测量结果 | — |
| 实现 | 可以改设计；必要时可以临时代行执行（要记录角色切换） | 在文件范围内实现并写测试 | 不改源码 |
| 测试与验收 | 审查证据、决定 `accepted` | 自测、写报告 | 在干净 checkout 上独立复核、做变异测试 |
| 结论 | 区分事实、假说和未验证项 | 如实报告全部结果和失败 | 只报告复核结果 |

规则：
- **同一任务的作者不能当它的验证者。**
- **测试通过不等于能力达标**；`completed` 也不等于晋升。

## 每轮闭环

**事实核对 → 统筹固定设计与参数 → 执行实现 → 执行自测与报告 → 独立验证 → 统筹验收或打回 → 登记下一步。**

## 双统筹如何避免冲突

1. 每个任务或实验只有一名主责统筹，负责最终配置和根目录状态。另一名统筹可以审议、提案，或者负责另一个互不冲突的任务。
2. 同一个文件在同一时刻只有一名编辑负责人。领取任务时写清文件范围，移交时写清已改文件、没做完的工作和运行状态。
3. 两位统筹意见不同时，先把两种主张、已有证据、能区分它们的最小实验和成本写进 `RESEARCH_LOG.md`，由主责统筹在授权范围内选择。只有超出用户授权时才去问用户。
4. ADR 一旦接受，要改就写新的 ADR 去替代它，不直接改旧 ADR 的结论。

## 本机资源（ADR-0009 全力跑，取代 ADR-0006 第 1–3 条）

- **不等空闲，直接全力跑。**
- GPU 分两档：
  - 轻量（Godot 渲染、小模型）随时并行；
  - 重型（LTX、扩散、大模型）全机串行，包括 Studio 网关上的 LTX 任务。接力台的闸门会自动处理。
- AinerZero 有实验在跑时不再挡 AWZ。
- CPU 上的内核生成、打包、评测可以和 GPU 工作同时跑。
- 只保留防崩溃的线：系统保留 16GB；磁盘剩余 ≥ 50GB；接电源才训练。

## 不可越权

- 不改 AinerZero、AinerHub_IDEA，不写它们的 artifacts 和账本。
- 不下载模型、大资产、字体、贴图；CC0 资源也要先得到用户同意。
- 不调用付费服务，不停用户的其他服务（omlx-server、Docker、网关等）。
- 执行者不提交、不推送；由统筹整合后提交。

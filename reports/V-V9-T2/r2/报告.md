## 4. 正向核对（仍然成立的部分）

1. `store_problems` 在 schema 全开下对契约正例返回 `[]`；上下文身份用**调用方固定的预期 SHA**核对，替换成自己重算的摘要会被 `trusted_context_identity` 拒绝（r3 §10.1）。
2. `train_eligible` 的五项交集与 r3 逐条一致：`external_derived` 默认拒训、`reproducibility=unverified` 拒训、分区非 train 拒训，均能正确给出 False。
3. 三类篡改**能**被抓（我的对照项，说明守卫不是空转）：`source.partition` / `provenance.upstream.eligibility` 被改 → `original_source_binding_mismatch`；`key_material` 被改 → `cache_key_mismatch`；`derivation.teacher_id` 被改 → `derivation_teacher_mismatch`；条目必备元数据缺失 → `MetadataIncompleteError`；顺序重写不同输出 → `nondeterministic_output`；顺序跨分区写入 → `CrossPartitionError`；Train Mode 构造教师 / World Mode 加载 feature 教师 → `ModeViolationError`；`set_mode('not_a_mode')` → `ValueError`。
4. 内容块 `output.bin` 被篡改时 `read_blob` 抛 `HashMismatchError` 并标 `broken`；`read_entry` 在引用块损坏时把条目标 `referenced_blob_broken`。
5. 锁协议：`--verify-locks` 16 种两进程组合全部互斥，"取锁后早释放"与"先占用再取锁"两类改坏都被抓（exit 0）；锁全部落在临时目录，未触碰真实 `artifacts/locks/`。
6. 纯 CPU：被验源码与测试中无 `mlx`/`torch`/`onnxruntime`/`coremltools` 导入。

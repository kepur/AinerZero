## 3. 六项核心技术审计与独立反例验证

### 审计一：跨 Checkout 重跑防范与中央台账相对路径穿透（关键独立反例）
- **漏洞证明**：在 `reports/V9-P17/evidence/audit_1_cross_checkout.py` 中构造两个独立 checkout（`checkout_a` 与 `checkout_b`），模拟批准已生效。
- **反例机制**：`spec.py:32` 定义 `REPO_ROOT = Path(__file__).resolve().parents[5]`，导致 `spec.PHASE1_ROOT` 和 `canonical_ledger_path()` 依赖当前进程所在源码树的相对位置。
- **实测结果**：在 `checkout_a` 中将 `arm2_seed0` 标记为 `completed` 后，在 `checkout_b` 中只要放置一个包含 `s1-phase1-prereg-prep-20261021` 实验的空合规 `control.sqlite3`，`canonical_ledger_state()` 判定为 `ok`，`output_root == spec.PHASE1_ROOT` 在 `checkout_b` 内部成立，查询 attempts 为 `[]`，从而彻底绕过跨 checkout 防重跑！
- **结论**：当前台账锚定仅防范了同 checkout 下非 canonical output-root，对多 clone/checkout 无法防重跑。建议一级统筹未来将 `canonical_ledger_path` 锚定到绝对宿主路径或引入宿主级 RunStore 互斥标识。

### 审计二：133,102s 墙钟超限之工程缺陷对账
- **现象审计**：作者报告第 9 节称中央台账历史累计墙钟达 133,102s（超阶段 14,400s 预算），导致规范根上任何训练均被拒绝。
- **根因分析**：在 `reports/V9-P17/evidence/audit_2_wall_seconds.py` 中直接只读分析 `control.sqlite3`。`src/ainerzero/runtime/lifecycle.py:392` 中 `wall_seconds=max(0.0, instant - row["created_at"])`，未判断终态（`state in ('completed', 'failed', 'stopped')`），导致已结束的历史 run 随真实日历时间无限膨胀（当前实测已涨至 211,859.9s！）。
- **实际执行时间**：从 `updated_at - created_at` 及 `run_transitions` 计算，3 个历史 prep run 的真实物理墙钟总耗时仅 **59.53 秒**，active 时间仅 **720.27 秒**。
- **结论**：此为 `RunRecord.wall_seconds` 动态计算未封闭终态的**工程缺陷**，而非真实阶段预算耗尽。不能因此降低保护线或抹除账本历史。

### 审计三：Arm1 评测入口功能真实状态
- **实测审计**：在 `reports/V9-P17/evidence/audit_3_arm1_eval.py` 中实测 `run_worker("eval", arm="arm1")`。
- **结果**：`worker.py:639-650` 无条件返回 `status="refused", refused_stage="arm1_has_no_checkpoint_binding"`。
- **结论**：Arm1 为已冻结的 D 候选模型（有固定身份与参数），本不依赖 S1 训练检查点。当前代码一律拒绝 Arm1，实属功能未实现。报告中不能宣称全部评测指标入口可用。

### 审计四：Few-shot 排他 stop 边界验证（协调消息 387）
- **实测审计**：在 `reports/V9-P17/evidence/audit_4_few_shot_stop_boundary.py` 中以真实 `runtime.step_sequence` + CPU 鸭型模型对比 r5 与 r6 边界。
- **复现结果**：
  - r5（`stop = support[-1] + 1`）：k=1 时请求单帧直接触发 `BackendError` 崩溃；k=2 仅记录 1 次转移（少 1 条）；k=4 仅记录 3 次转移（少 1 条）。
  - r6（`stop = support[-1] + 2`）：k=1 产生 1 条支持转移，k=2 产生 2 条，k=4 产生 4 条，且 query 连续性与不相交性保持完整。证实 r6 修复有效且承重。

### 审计五：冻结 stop_rules 有限性负对照验证（协调消息 389）

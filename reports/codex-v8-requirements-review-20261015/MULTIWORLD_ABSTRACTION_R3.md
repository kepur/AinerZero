# 多世界的高级抽象与 AinerZero 的理解方式

日期：2026-10-15（Europe/Istanbul）；主责：Codex。  
性质：设计提案，承接用户提出的写实、赛博朋克、历史时代、石器时代及科技/魔法混合世界。只新增本审议文件及来源清单；不修改既有契约、ADR、模型、预算或任务状态。

## 1. 核心抽象

**一个世界是有作用域、可组合、可执行、可追溯的一组对象、机制和历史。**

它不只是题材标签，也不只是外观资产。对系统要分开回答：

1. 这个世界如何运行？——可执行机制。
2. 这个世界包含什么文明、技术、人物和关系？——语义与内容。
3. 这个世界如何被观察和表现？——感官、画风、表演和镜头。
4. 谁在什么时间、凭什么证据相信什么？——知识与信念。

AnimeWorld 负责维护世界并执行已定义机制；当前 LLM 结合查询、规划、试演与评价工具制作作品；AinerZero 将来在受限观察下学习机制和行动。三者使用同一套世界作用域，但不共享未授权真值。

本文把用户的“欧美80世纪、90世纪”按上下文暂理解为欧美 1980/1990 年代。正式建世界时应记录确切年代、地域与来源，不能由这句示例自动生成历史事实。

## 2. 题材拆成可独立组合的七项

| 维度 | 保存什么 | 必须避免的混淆 |
|---|---|---|
| 时空与文明 | 世界日历、地域、历史阶段、社会制度、文化习惯、知识/技术分布 | 年代改变不自动改变重力；文化规范不等于不可违反的物理定律 |
| 基础机制 | 运动、接触、材料、光学/声学、气候，及声明的计算近似 | 看起来真实不等于现实验证；引擎支持某特效不等于机制已接入 |
| 身体与对象 | 类别、组成、几何/碰撞代理、质量、传感器、动作接口、资产与身体版本 | 换画风不应暗改身体能力；同名不同世界不自动是同一实例 |
| 技术与特殊能力 | 工具、义体、能源、法术、传送、修炼能力，以及前提、效果、代价和限制 | 赛博朋克不自动拥有反重力；“会魔法”不是可执行规则 |
| 语义与社会关系 | 用途、可交互点、拥有/所属/关系、目标、信念、法律与习俗 | 法律禁止不等于物理不可能；角色说法不等于世界事实 |
| 视觉表现 | 写实/平涂/线稿、材质表现、阴影、美术光照、几何外观变体与相机 | 物理光源改变与美术阴影覆盖必须分开；写实画面可表现虚构机制 |
| 表演与拍摄 | 动作细节、节奏、夸张程度、表情、声音、口型、剪辑与镜头 | 镜头停格不是世界时间停止；剪辑跳切不是人物真的瞬移 |

世界/分支/revision/区域/时间/对象是以上各项共同的作用域；出处、证据和确定程度是各项共同的元数据，不塞进某一个题材字段。

题材模板只是这些配置的起点。允许本地覆盖，必须经过兼容检查。一个“石器社会”也可以位于一部有外星飞船的架空故事里：不同群体有不同技术知识，不应强制整个世界只属于一个技术等级。

## 3. 示例：同一体系能表达哪些世界

| 示例 | 基础机制 | 文明/技术 | 身体与能力 | 画面/表演 |
|---|---|---|---|---|
| 历史写实的 1980 年代城市 | 选定的地球近似物理 | 具体地区与年代的资料约束；缺信息留未知 | 普通人体、实际登记的工具 | 写实外观、自然表演 |
| 1990 年代城市的日漫改编 | 可沿用上一类基础物理 | 换成相应地域年代内容 | 普通人体；明确登记新增能力才生效 | 赛璐璐、可选一拍二；不凭拍法宣称运动定律变了 |
| 写实石器社会 | 同样可以是地球近似物理 | 该世界定义的工具、材料、生产与社会知识 | 人体与具体工具；不假设所有人行为相同 | 写实或动漫均可 |
| 写实赛博朋克 | 可仍沿用地球近似物理 | 都市、网络与义体等已定义技术 | 有功率/力矩/能源约束的义体 | 霓虹只是视觉主题之一，不强制所有场景同一色板 |
| 科技与魔法共存 | 基础物理加显式特殊机制 | 技术知识、法术体系、派系并存 | 人、义体人、法师；不同对象与机制耦合不同 | 可以完全写实，也可以传统日漫 |

自然动作、物理可行动作和角色行为策略也需区分。一个写实角色可以自然地表演某个法术，但法术效果依赖世界明确允许的机制。可行不代表角色一定愿意执行；人物目标、社会关系和知识影响选择。

## 4. 机制包：可以组合，但不能靠任意覆盖拼凑

每个机制包至少声明以下内容：

| 字段 | 作用 |
|---|---|
| 身份与实现 | `rule_id@version`、依赖、代码/配置摘要、接口版本、可执行适配器 |
| 作用域 | 世界/分支、区域、时间范围、对象类别或具体实例、身体适用范围 |
| 前提 | 何时激活，能量/接触/权限/施法/环境条件；未知前提如何处理 |
| 状态与资源 | 读取/写入哪些状态、持续效果、消耗与恢复、冷却和容量 |
| 效果 | 力/约束/状态转换/事件、感官可见性及失败效果 |
| 组合语义 | 与其他机制并存、叠加、抑制、替代或冲突；同 tick 执行阶段 |
| 边界与撤销 | 离开区域、跨规则边界、效果结束、取消或世界修订后的行为 |
| 证据与限制 | 作者定义、现实资料、仿真验证、已知近似、未验证能力 |

### 一个混合世界的例子

一个世界同时有普通人、义体人和法师：

- 普通人遵循登记的人体行动与环境机制。
- 义体通过驱动器增加可施加的力，受电池、功率、结构强度和接触条件限制。跳得更高可以来自执行器能力，并不一定改变世界重力。
- 悬浮法术提供独立的支撑/约束效果，受施法条件与资源限制。资源到支持力的映射属于该虚构世界定义，不能冒充现实测量。
- 禁魔区按声明抑制与法术耦合的效果，不自动关闭电子设备或重力。
- 若某种义体也使用魔法能源，它是否被禁魔区影响，取决于该对象的明确耦合关系。

“禁魔优先”只在声明的作用域及相应阶段有效。应指定何时判定区域、何时抑制施法、何时积分运动与解决接触；未定义冲突就拒绝编译，不能让最后加载的配置悄悄决定物理结果。

### 类型不同，组合方式也不同

- 重力场参数可以空间叠加或按明确区域选择。
- 接触约束由选定求解机制统一处理，不把两套互不知情的物理结果相加。
- 传送是有前提与落点条件的离散状态转换，不能强行当连续行走轨迹验收。
- 法律和禁令通常影响行为决策与后果，不应一概变成引擎拒绝非法动作。
- 影视夸张形变可以仅发生在表现层；若确实改变世界身体尺寸、碰撞或因果结果，必须登记为世界机制。

同一个世界还可以有普通区、低重力区、禁魔区和特殊时间区。区域规则不是一句主题描述；跨边界时的状态和时钟语义需要可执行定义。初期不必实现这些全部机制，只实现明确支持的小集合；未支持返回清楚原因。

## 5. “真实、想象、未来”至少沿三条轴记录

一个 `real_or_fake` 布尔值不足以表达用户需求。

### 5.1 对哪个世界为真

保存 `world_id / branch / revision / region / valid_time`。

“某种火焰能冻结水”可以是世界 A 的作者设定，也可以在 A 的模拟中得到验证；它不会因此成为现实世界或世界 B 的规律。同样，原著版和用户改编版可以有不同规则，各自保留出处与谱系。

### 5.2 是什么来源、什么证据

- 现实测量/有出处资料：记录实际来源、适用条件与误差，不能只写“现实”。
- 原著明示或用户定义：可以成为所选小说世界的 Canon，但仍保留作者来源。
- 仿真实际执行：证明在该模拟器、版本、参数下发生了什么；AWZ 导出仍按现行政策标为 `external_derived`。
- 角色或教师主张：是谁说的；可能错误、撒谎或只在局部成立。
- 模型预测/想象：尚未实际执行的假设结果，不得变成新的自观察。

**虚构世界中的真实模拟经历，与模型尚未执行的想象，不是同一种来源。** 也不能因为画面写实就把模拟片段标成现实摄影。

### 5.3 谁目前知道多少

分别记录引擎权威状态、角色信念、AinerZero 信念、导演/用户意图。

引擎知道某法术真的存在，不意味着场内角色知道；角色说“这里不能飞”也未必正确。AinerZero 的信念必须关联当时可用的观察和辅助来源，允许多个解释与未知，不使用后来取得的证据覆盖过去已记录的预测。

因此，一条知识应表达成：**在什么世界/条件下，谁提出什么主张，何时可知，由什么支持，目前是设定、已验证、待验证还是被反驳。** 未校准的置信度留空；不随手编百分比。

“未来想象”属于现实参照与来源性质；“预测未来状态”属于时间与模型行为。未来题材中的过去事件也可能已经在该虚构世界发生，两者不能混淆。

## 6. AnimeWorld 怎样生成和执行这些世界

```text
文本/小说/参考资料
    ↓ 提取带来源的设定、未知与冲突
世界草案：文明 + 对象/身体 + 机制包 + 技术/能力 + 关系
    ↓ 依赖、单位、能力、作用域与冲突检查
用户采用/已授权流程 → 固定世界 revision 与规则摘要
    ↓
世界运行：状态 + 动作 + 生效机制 → 新状态/事件
    ↓
不同风格/镜头/声音表现 → 观察与作品
```

可以用两行表示核心分离：

\[
s_{t+1}=F(s_t,a_t;\rho_{w,r,t,e},b),\qquad
o_t=R(s_t;v_t,p_t,\sigma)
\]

- `s` 是世界状态；`a` 是动作。
- `rho` 是对当前世界、区域、时间和对象生效的机制；`b` 是身体/工具能力。
- `o` 是观察；`v` 是视角；`p` 是表现设置；`sigma` 是已登记的传感器/观察配置。
- 同时包含角色策略、随机事件或有状态模拟时，把相关状态与随机条件显式纳入运行身份，不假装这两行已经完成了通用物理。

换画风主要改变观察生成；换义体改变身体能力；换年代主要改变文明内容与可用技术；加入低重力机制才改变相应动力学。部分风格需要几何/Rig变体，必须显式映射，不能默认所有变换都只改 Shader。

改变机制必须产生新修订，或登记为带生效时间的世界事件。旧运行、旧预测、旧镜头和旧评测不倒改；受影响产物标记需要重建。

## 7. AinerZero 怎样“理解”，而不是背题材标签

建议的长期目标是：**共享对象/关系/动作表征，加上对当前机制、身体和上下文的不确定判断。** 不预设每个题材都必须另训一个大脑，也不保证同一个小模型能无代价覆盖所有任意规则。

模型应学习的过程是：

```text
当前可用经历
    → 估计对象与状态
    → 提出当前机制的候选解释
    → 预测动作结果与不确定性
    → 选择有用、可达的试探
    → 取得反馈并修正信念
```

例如看见一个人悬空，可能是地面支撑、隐藏绳索、喷射器、低重力或法术。仅靠题材和一张图不一定能区分。需要时间观察、动作干预或其他传感信息；证据不足时保留多个解释。

### 两种学习模式必须分别登记

1. **规则已告知**：提供允许的结构化规则/教师提示，评测模型能否组合并正确预测。这属于明确辅助，不声称它自己发现规则。
2. **规则未知**：学习者只看允许的观察/动作反馈，评测机制识别、适应和行动收益。确切规则包 ID、私有参数、隐藏角色能力和题材答案不直接喂给学生。

世界/规则身份首先是审计与记忆作用域，不应成为“看到某 ID 就知道正确答案”的捷径。评测需要对这些 ID 改名/隐藏的对照；可用的身体和世界切换信息也要事先登记。

### 共享与隔离

- 可共享：物体持续性、接触关系、空间/时间推理等经过验证的表示与技能。
- 应带条件保存：某地重力、某种身体的能力、某法术的前提与代价。
- 应按世界隔离：角色事实、小说 Canon、已访问区域与局部机制信念。
- 切世界时切换相应上下文/记忆；不能把世界 A 的法术当成世界 B 的普遍事实。
- 仅在上下文里更新信念与真正更新权重是不同过程；是否学习持久参数仍走独立登记、预算和防遗忘验收。

这与在未知环境中学习任务/机制信念并据此行动的研究方向相容。例如 [VariBAD](https://arxiv.org/abs/1910.08348) 研究了从经历推断未知环境、在行动中考虑任务不确定性。这里只借鉴问题分解；该论文不证明 AinerZero 已实现，也不保证学会任意魔法机制。

视觉变化也应与机制变化分开控制。[Domain Randomization](https://arxiv.org/abs/1703.06907) 曾在物体定位任务中研究改变仿真外观以迁移到真实图像；它不证明视觉随机化会自动得到跨世界因果理解。

### 当前真实边界

AinerZero 当前仍是受限的 C0 符号模型，历史记忆未解决，训练暂停。现有经历/时空契约提供世界、来源、假说、想象、证据与修订的一些基础；没有完整的多世界机制推断、视觉理解或魔法/文化语义能力。

新增外层 JSON 或知识图谱不会使这些能力自动出现。将来需要单独完成观察/动作/身体接口、模型表示与训练方案，并做独立评测；不在本稿里更换现有模型或启动研究。

## 8. 怎样验收这套抽象有没有用

| 对照 | 应保持什么/改变什么 | 在检验什么 |
|---|---|---|
| 同世界同规则，写实↔日漫 | 世界状态与因果不变；观察变化 | 是否把画风误当物理规律 |
| 同画面主题，普通↔低重力 | 身份与主题尽量相同；机制变化 | 是否从结果识别机制，而非背标签 |
| 石器↔近代/未来工具 | 基础规则可相同；工具和身体能力变化 | 是否区分文明/技术与动力学 |
| 义体+法术+禁魔区 | 按声明分别影响机制，保留电子/法术耦合差异 | 是否理解机制组合、前提和作用域 |
| 规则在区域边界变化 | 边界与事件已登记；预测按条件更新 | 是否会更新上下文与识别失效规律 |
| 原著↔改编分支↔模型想象 | 各分支证据与来源隔离 | 是否把虚构设定/未执行预测泛化为现实事实 |
| 新名称、新资产、新组合 | 不改变机制答案但去掉熟悉 ID/外观 | 是否具备所声称的组合泛化 |

训练/开发/最终按世界谱系、规则组合、资产/模板族及评测目标划分。换一个 world_id 或种子，不足以排除同源世界泄漏。精确划分与门槛在具体研究协议中登记，本稿不新增门槛或实验。

## 9. 对现有规划的最小增补

现有 v8 §3/4 已有 World Rules、Canon、世界原型和来源设计，§9 已有独立风格。因此方向可以继承，新增的是把这些设计收口成可组合、可执行、可学习的接口。

建议由当前负责人在现有模块下分别登记：

1. **世界描述与作用域**：将题材解析成文明、机制、身体/能力、语义、表现等独立字段，保留未知与出处。
2. **机制包与组合检查**：先做少量明确机制，声明效果、资源、作用域、抑制与冲突；编译后固定摘要。
3. **来源与信念边界**：引擎事实、作者设定、角色说法、学生估计、模型想象分别引用。
4. **表现/机制对照场景**：复用小场景，改变画风、工具或单一机制，验证日志和行为确实相应变化。
5. **AinerZero 后续协议草案**：仅设计规则告知/规则隐藏两种任务与必要接口；恢复与真实模型工作仍由用户另行决定。

第一批可以仅围绕同一角色和小物体定义三个配置：普通物理、同物理不同年代/画风、带有明确条件的悬浮与禁用区域。先在世界系统端证明可执行，再谈学习者的理解。代码、CPU测试、真实运行和模型学习分别交证据。

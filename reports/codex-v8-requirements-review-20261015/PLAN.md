# v8 需求与 Claude 规划的平级审议及补充计划

日期：2026-10-15（Europe/Istanbul）

本次编辑归属仅为本目录内的审议稿、需求对照与来源清单。现有任务卡、根目录决策、源码、运行登记和证据未改动。

## 1. 结论

**总体方向成立，建议沿用 Claude 的分层和现有任务，补齐产品交付链、世界数据闭合与验收边界。**

分享对话的核心是：以持续存在、可编辑的世界驱动动漫制作，先由现有 LLM 和 Blender 出成果；独立的 AinerZero 以后学习世界规律。后台运行、人物一致、多风格、声音与动作、可挂载小说世界、图片/首尾帧输入，以及能够积累经验并改进，都是目标。

Claude 已正确处理：世界真值归 Python 内核、Blender 被选为当前主引擎、Godot 保留为未来实时后端、AinerZero 独立、Forge 独立管理训练资产、既有文件原地保留、当前机器按 M2 Max/96GB、课程 G0–G7 与参照模型 W0–W3 分开命名。

最需要补的不是更多平台模块，而是一个明确的近期交付：

> 一段文本生成一个可重开、可修改的世界，驱动同一角色完成动作和一句对白，经 Blender 后台渲染，输出 5 秒动漫短片与完整编辑源。关闭 AinerZero 后，这条生产链仍成立。

这里的 5 秒、480p、24fps 是建议的目标规格，继承 v8 P0 的最小成片方向；不是性能测量、现有成果或本次运行授权。

## 3. 需要修正或补充的九项

### 审议项 01：当前入口和实际路线未同步

**依据**：AWZ README、COORDINATION 和 ARCHITECTURE 仍以 R1/Godot 为主叙事；ADR-0010 和 D-007–D-010 已转向 Blender/P3。AinerZero README、AGENT_TASKS 也有早期“可领取 E13b”等当前式表述，与较新的暂停决定并列。

**建议**：由当前文件负责人统一入口的“截至日期、当前阶段、主责、下一门、暂停项”。保留历史正文，明确历史段落；新增规划优先复用已排的 P3-G1 北极星文档，其他入口引用它。把“选定 Blender 为主引擎”和“Blender 制作链已验收”写成不同状态。

**判断**：文档冲突成立；不表示 Claude 最新架构方向错误。

### 审议项 02：缺一张负责最终短片的集成任务卡

**依据**：P3-A3 是 8 帧、四通道的后台适配检查；P3-B1 是 3 种子×3 机位静态预览；P3-C1 是至多 5 轮参数调整。这些卡各有作用，但没有一张验收完整的“文本→世界→动作/声音→视频→重开编辑”。

**建议**：保留原卡，新增一项产品集成工作包及其非作者独立验收。其依赖是最小世界源、Blender 通道切片、角色/风格适配和制作时间线，而非全部 Forge/Relay 升级完成。

**新增交付**：5 秒/854×480/24fps 短片，120 个输出帧；世界源、版本锁、EDL、音轨与口型轨、可重建的 `.blend`、代表通道、报告。视频和可编辑世界同时交付。

**判断**：近期实施计划存在交付缺口。8 帧通过仍只表示相应适配工程通过。

### 审议项 03：生成器需要回到唯一世界源，避免只得到 `.blend`

**依据**：P3-B1 规定程序化街道、对象清单和 manifest，但未明确该清单如何成为世界源、进入稳定实体注册、碰撞/语义和 WorldCommand。已有 Scene Compiler 只支持明确子集，并拒绝其他操作。

**建议**：生成器输出中立的场景片段；片段写入版本化世界源后，再由编译器/内核和渲染器消费。至少包含稳定实体 ID、资产版本、父子关系、米制变换、碰撞代理/纯装饰声明、生成器版本与种子。不要假设现有编译器已支持建筑与所有材质属性；按实际子集增补契约。

**可编辑世界的最小验收**：保存后新进程加载；移动一栋建筑并重新编译；风格切换不改变实体身份、动作时间和碰撞；不依赖 Blender 当前打开的会话。

**判断**：现卡未闭合这条数据路径；尚未运行，不能认定实现已绕过内核。

### 审议项 04：世界编辑和挂载不能长期停在文档

**依据**：P3-E1/E2 目前交付协议/映射设计；用户要求的是一本小说一个可挂载世界，可对话改、续写、复用。

**建议**：近期先实现小世界包，不建完整大陆系统。最小包包含世界源、实体、版本化资产/风格引用、时间线、生成器配方、来源与内容摘要。先支持创建、保存、挂载、卸载、模板派生，以及三个编辑动作：改建筑、改灯光、移动角色。

WorldCommand 用 expected_revision 和幂等 ID；先预览，再由已授权的提交流程形成新 revision；撤销生成新修订，旧修订保留。静态世界修改后重新编译受影响时间段，不引入 Blender 回写真值。

**判断**：需求有设计归属，缺后续实现与运行验收任务。长篇小说解释和区域懒加载可以继续留到后期。

### 审议项 05：声音与运行时 LLM 接入需要进入近期制作链

**依据**：PERFORMANCE.md 已有台词、对齐和口型设计，但 P3 主路径没有相应任务。模块 3.1 也明确：开发 agent 经 Relay 可用，产品运行时适配接口未做。

**建议**：先接一个有实际可用入口的提供方，产出受 schema 约束的意图/场景计划，再编译为命令。对已记录输入允许无模型重放。不能把“Claude/Codex 手动完成一次任务”算成产品已能自动理解文本。

声音先做一句台词：先锁主音频和对白时长，再排动作、镜头、口型及音效。优先核对并复用已有 TTS/对齐/混音/编码入口；不可凭旧文档认定服务当前可用。首片用已有授权、可用的音频资源；多语言扩展后置，保留语言独立时间线。

**判断**：设计已有，近期实施缺口成立。第一步核接口，不另建视频生成 UI。

### 审议项 06：动漫质量和 EEVEE/Cycles 选择要按证据决定

**依据**：P3-A3 允许代理几何；P3-B1 的预览与自评主要覆盖街道元素存在；ADR 把 EEVEE 用于预览、Cycles 用于成片。用户关注的是日漫质感、人物稳定和制作速度。

**建议**：代理几何只用于适配工程，进入动漫交付前必须用登记角色和 Blender 版身份/风格约束。验收分三项：结构正确、人物/时序稳定、美术质量。元素齐全不能等同日漫品质。

EEVEE 应先作为“能否满足首片画质”的候选路径测量；建议不要把 Cycles 设成一切成片的强制前置。若需要改变 ADR 的预览/成片分工，由主责整合修订。Cycles 只为明确的光影缺口做有界对照。当前不承诺实时、固定倍速或固定训练时长。

**需要记录**：冷启动构建、预览、正式渲染、QA、编码和局部重渲染的总耗时；每帧 p50/p95、失败、峰值内存、固定质量档。规则帧可随机跳转的性质也要在 Blender 消费路径重新验收。

### 审议项 07：美术自评可指导搜索，不能单独证明自驱能力提高

**依据**：P3-C1 已诚实标注同一 agent 主观自评，P3-C2 也已有独立盲评。这是好的起点；但仍缺预留场景、冻结评价器、回归与晋升边界。

**建议**：把当前目标称为“有界美术参数迭代”。先固定参数空间、基线、总预算、停止条件与选择规则；保留所有候选和失败。用不同种子、机位和少量预留场景检查收益，独立盲评同时核对身份、时序和资源成本。参数搜索成功后，再决定是否值得训练评分器/Art Policy。

经验记录至少包括：输入意图、世界 revision、资产/风格摘要、变更前后参数、图像/视频摘要、评分理由、用户确认、评价器身份、实际成本。Tag 只用于检索/约束；它不是自动成立的训练标签。世界理解、美术偏好、工程优化三条目标分别保存。

**判断**：已有局部迭代设计；长期自驱训练与晋升未验证。补门后可以逐步成长，不必先造完整自治平台。

### 审议项 08：参考图和首尾帧应保留明确下一入口

**依据**：v8 已覆盖这组需求，模块 1.9/1.10 也有归属；P3-G1 将其置于远期，没有直接下一任务。

**建议**：可以后于首片，但应登记进入条件和最小任务：先接一张参考图，提取可编辑的建筑/色板/光照/镜头约束与不确定性；再试首尾两组约束，求解动作和相机，报告可满足、部分满足或不可满足及回退方式。

先保留五种模式的概念归属，当前只实现 WORLD_NATIVE。其余模式各自通过实际适配器能力核对后才开放；不要求为五种模式立即建全部代码。扩散结果不能自动宣称具备可编辑世界。LTX/现有网关优先复用，但兼容性仍待届时核对。

**判断**：不是完全漏需求；是近期计划中没有清楚的接续门。完整多模态重建、完整视频扩散、VR 仍可后置。

### 审议项 09：基础设施和独立层的故障边界需要更具体

**依据**：Forge、Relay 升级路线合理，但 v0 仍有少数语义缺口；P3-G1 的“关掉任何一层，其余照常运转”也过于绝对。

**建议**：

- 按实际依赖写降级：停用 AinerZero 不影响制作；停用神经美术层回到规则风格；停用渲染器仍能编辑世界，但不能出片；停用训练平台仍能按既有模板渲染。对必需依赖返回清楚错误。
- 首片复用现有有界 runner；更完整的统一仲裁、作业层、模型注册表逐步接入，不把其全部升级设成首片前置。
- 审议 Relay 仲裁草案的 TTL：文本同时规定“过期释放资源”与“不杀持有者进程”。若计算进程仍在运行，不能仅凭 TTL 到期宣称真实资源已空闲并发放重型租约；需保留不确定占用/观察进程状态的恢复语义。
- Relay 的 authorization_ref 格式检查只是引用校验；实际运行入口必须验证对应系统的有效登记，不能把格式合法当运行授权。
- Forge 的不可变包状态与可变注册表分开；APACK_FORMAT 的“许可项缺失按 false”和 F1-A1 的“缺项拒绝”需统一为明确规则。建议完整 manifest 必填，缺失就拒绝；权限布尔值不能自报扩大源许可。
- 同一世界衍生的换风格、换镜头、编辑版本和共享模板须保留 lineage 分组；仅不同 seed/world_id 不足以证明无近重复泄漏。选择哪种隔离强度取决于评测声称的泛化范围。
- `.aworld` 保存世界与编辑历史；`.apack` 是某次用途明确的不可变素材/数据视图。挂载世界不等于准入训练；暂停 AinerZero 期间只记录合法来源，不训练它。

这些是规划/契约审议发现，不是本轮执行了仲裁器或挂载器后的漏洞测试结论。

## 5. 首个成片的建议验收合同

### 5.1 作品与源双交付

- 一个固定小世界、一位已有登记角色、一段简单动作、一个镜头段落和一句对白。
- 854×480、24fps、5 秒：120 个输出帧。默认第 n 帧映射到 tick 5n；输出帧率不改变内核 120Hz。
- 主音频先固定；如最终时长不等于 5 秒，必须在登记前决定截段或调整片长，不能靠事后丢帧凑规格。
- 完整世界源/修订、资产与风格锁、EDL、表演轨、音轨、口型轨、构建参数、RenderJob/Report、视频、代表性通道及 `.blend` 缓存。核心源文件足以重新构建，`.blend` 不是唯一权威。

### 5.2 分开回答六个问题

| 问题 | 证据 |
|---|---|
| 真能后台运行吗 | 实际后台进程、命令、日志和产物；不能只凭 argv 中有 `-b` |
| 世界/角色一致吗 | 相同世界 revision、实体和角色资产锁；轨迹/事件一致；身份和调色板逐项检查 |
| 真有连续动画吗 | 实际播放完整片段，检查脚滑、穿模、线条闪烁、镜头切换；8 张静帧不能替代 |
| 声音可编辑且对齐吗 | 台词、说话人、主音频、对齐、口型轨有共同时间映射，误差门在看结果前登记 |
| 能重开再改吗 | 新进程重建；改一次灯光或建筑后局部重渲染；撤销后逻辑状态恢复 |
| 美术和效率够吗 | 固定质量档、独立视觉判断与耗时/内存；同样世界另机位/少量预留场景核对，不作未测的倍速承诺 |

工程单元测试、Blender 实际消费、作品播放、美术独立评价是四种证据，分别报告“成立/不成立/未验证”。

## 6. 当前契约还应提前澄清的细节

1. **RenderJob 身份**：绑定世界 revision、源/状态日志摘要、EDL 摘要、角色/风格/资产版本和内容摘要、后端与采样/色彩设置；渲染期间不可变化。
2. **通道语义**：depth 的线性单位/相机空间/背景值；normal 的坐标系；object_id 的稳定映射；RGB 的色彩空间与变换。不要把数值图像用普通色彩变换处理。公开观察与私有 ID 映射的用途继续分开。
3. **投影验收**：P3-A3 的“可见像素质心对比世界实体原点投影”只适合特定对称测试几何，一般实体的可见质心不等于投影原点。应选择有定义的标记点/关键点、可计算包围体或基准轮廓；预先定义遮挡分母、视锥外和裁剪规则，再登记像素误差门。
4. **复现范围**：相同环境下的数值清单、ID 图像、RGB 各有独立复现等级。跨后端验证逻辑和适配质量，不承诺逐像素相同；换后端不自动证明世界脑迁移成立，也不自动意味着旧模型必须重训。
5. **重复与恢复预算**：明确作者两次渲染和独立一次渲染各自预算，区分单次/整卡上限。未实现的跨进程训练恢复不可由 Relay 的 resume_argv 推导为已可用。
6. **插件最小面**：先消费现有中立 JSON/资产引用；OpenUSD、MaterialX、glTF 等保留到 P3-H1 核对版本与实际损失，避免多种交换格式齐备成为首片前置。

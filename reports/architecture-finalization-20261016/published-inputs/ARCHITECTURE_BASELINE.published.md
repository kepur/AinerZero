## 2. 固定的职责与不变量

| 职责视图 | 组件与唯一权威 |
|---|---|
| Control Plane | **AinerRelay / relay-runner** 管任务、租约、监督、恢复交接与复核；真实模型运行仍通过现有 CLI、共享锁、RunStore 与预算/资源守卫。作业监督不等于已实现自动续训。历史 Serafina 名称不阻塞当前设计，也不据此另建运行时 |
| World Plane | **AinerHub** 唯一写入持久区域、地标、实例、事实和版本，复用现有 Blender worker；**AWZ** 唯一负责运行、时间、事件、传感、确定性求值及运行快照，只保存 Hub 的只读派生输入。渲染器和物理后端可替换 |
| Learning Plane | **AinerZero** 保存信念、预测与 FAST/MID/SLOW 记忆，研究 MLX 小模型；**Forge** 管来源、分区、封存和资格。学生残差只改信念，不改生成器真值 |

三平面是职责视图，保留制作脑、世界系统、世界脑三系统；不是三套新运行时。继续固定：

- E3 五元组版本基准复用，不另造第二套版本/事务框架。现有 `awz.P3.E3` 已有 CAS、幂等、源摘要和恢复设计，尚未实现验收。
- 世界真值、受限 Observation、自身 Inference 分开；原始世界事件、隐藏接触、真值 ID、世界 dirty/fallback 不进入学习侧。可解析引用和教师输入同样受观察截止时间约束。
- A2 时间白名单、来源与 actor 独立；AWZ 经历仍 `external_derived`，默认不可训练。ADR-0005 未在本轮修改，当前没有新批准的经历训练例外。
- T1 单锁全程互斥、内容块与来源条目分开保留；共享同一 blob 不共享来源资格，跨分区引用拒绝。详细候选须完成下节补修。
- 世界侧稀疏更新包含持续动力学、宽相新接触、依赖传递闭包和安全回退；学习侧只依据允许观察、已执行动作和自身信念。正确性和速度分别验证，30% 只是研究目标。
- 位姿、右扰动、协方差和锚点按 G1 约定。旧科学门、种子、预算、数据分区、检查点和负结果原样保留；新研究臂逐项预登记。

Event 候选的设计补修包括：日志命名空间与唯一 ID、同 tick 次序；快照事件前缀及关系的因果截止；可信 run/base 版本时间线绑定；接触双方和类型登记。不能只重算哈希就宣称运行来源完整。具体失败证据见 [A9 契约报告](../AnimeWorldZero/reports/V-V9-A8/codex-v101-20261016/REPORT.md)。

教师缓存候选的设计补修包括：AWZ 来源固定为 external_derived 并核对不可变上游记录；as_of 使用 blob 的真实输入时间、与条目副本和 Observation 时间域绑定；ADR 批准必须解析可信登记，当前空批准集合全部拒训；derivation 的模型、权重、预处理指纹与 blob 逐项一致。不能凭可编辑来源字段或非空 ADR 字符串授予资格。具体失败证据见 [T17 报告](reports/V-V9-T1-r2/codex-v101-20261016/REPORT.md)。

这些是冻结的边界要求；子契约只能在这些要求内补齐，不能为了让测试通过而改政策。完整消费者、锁集成、真实仿真或模型性能不作为本轮文档定版的实现前置。

## 4. 已落地的任务顺序

所有后续实施都先过 `awz.V9.A10`，并保留各卡业务依赖；本次不办理总门。原19张实现卡 blocked，新增世界侧 B9/B11 为 draft，均已加总门；科研/教师扩展草稿另须原授权与预算。放行时由统筹逐张核依赖、范围与编辑负责人，不批量清空依赖。

| 顺序 | 工作与主卡 | 验证/放行要求 |
|---|---|---|
| 现在：文档与只读复核 | Event：AWZ A8→A12；教师：AZ T1→T18；基线：AZ A7→A8；其余已登记只读卡按自身条件领取 | 无产品实现、模型或 GPU；候选补修保留原件与失败 |
| 1：基线、接口、校验 | AZ A2、B2、G3；AWZ A3/D2/D4；Forge A2 | 用户明确同意代码开工；G1/G2、A2 契约、Forge 与各卡原复核依赖照旧 |
| 2：缓存与执行模式 | AZ T2→T3；教师候选及 Forge 映射一致 | T1 新修订先经 T18；验证真实双进程锁、可信来源、分区、时间与全部指纹绑定 |
| 3：世界运行、受限传感、考场 | AWZ P3.I2、V9.B1→B3；E3→E5 | I1 与修订 Event 契约、A3 与 Forge 前置保留；实际资产加载路径和同观察异未来测试必须独立执行 |
| 4：世界侧工程验证 | AWZ B11→B12（E0 小样），B9→B10（E2a） | I2/Event 前置；活跃集合、宽相、闭包迭代或安全回退；完整成本对比；批量生成另批运行预算 |

## 5. 定版后的维护规则

1. 主架构 r5 是当前采用的设计正文。日常实现、修 bug、测试证据、进度和基线内细化写入任务与模块文档，主架构保持稳定。
2. 改职责/权威写者、公共接口语义、来源与训练资格、观察可见性、已有科学门或预算，先登记 ADR/迁移与回滚方案，保留本基线和哈希，由非作者复核后发布新修订。未获批准不改变现行政策。
3. 出版勘误只改状态、链接和版本指针，保存前后身份并独立核对；不以“勘误”掩盖接口或科学门变化。子契约因补修升版，在兼容基线边界内不强迫重写主架构。
4. 一张实现卡配一张非作者验证卡；完成、测试全绿、工程验收、模型能力通过与生产验证分别报告。负面报告和原失败原样保留。
5. 基线 JSON 冻结主设计与本次发布证据的身份。候选文档的本次字节存为取样；live 文件补修不构成旧取样被覆盖，也不自动进入采用状态。变更日志与新批准引用另记新报告，不静默替换已发布基线。

本次没有产品代码、模型运行、训练、下载、安装、付费、git 提交或推送。现有 Relay 服务只作任务登记与复核，不替代运行授权。

# S2 结案报告勘误：训练数据生成器的寻路方向缺陷

一级 claude，2026-11-09。**非作者复核已确认**（`ainerzero.V9.P200`，报告在本目录 `review/`，从零写脚本独立重现）。结案报告 `reports/V9-S2-CLOSE/REPORT.md` 原文不改，本文件是对它的补充。

## 1. 缺陷

`src/ainerzero/v9/experiments/s2/data.py`（SHA `49f8bcf3…`）第 229、252 行：

```python
dist_from_goal = compute_pose_bfs_distances(layout, current_goal)
```

`compute_pose_bfs_distances` 是从起点沿动作方向的**正向** BFS，它算的是「从目标走到各位姿要几步」。`_find_path_step` 却把它当作「从各位姿走到目标要几步」，并在上面贪心下降。

位姿图是有向的（只能前进，不能后退），这两个距离不相等。贪心的结果是智能体转身背对目标，到达局部极小后返回 `ACTION_WAIT`，停在原地。

这与设计稿 r2 §2 的要求不符：「带噪 BFS 段：随机选远处目标，沿最短路径走」。

## 2. 实测（纯 CPU、只读）

**寻路本身**（`s2_bfs_defect.txt`）：40 个世界、200 组长目标、无噪声、上限 200 步。

| 距离场 | 到达目标 | 卡死在 WAIT |
|---|---|---|
| 现有（正向 BFS） | 0 / 200 | 200 / 200 |
| 修正（反向多源 BFS） | 200 / 200 | 0 / 200 |

**真实训练集**（`s2_train_data_audit.txt`）：`artifacts/v9/s2/phase1/datasets/train`，8000 回合，按环境步计。

| 指标 | 实测 |
|---|---|
| 动作占比 | FORWARD 21.9%、LEFT 18.7%、RIGHT 18.7%、**WAIT 40.7%** |
| BFS 段内 WAIT 占比 | **60.6%** |
| 非 BFS 段内 WAIT 占比 | 26.9% |
| 一回合走过的不同格子 | 中位 14，最小 1，最大 48（一个世界约 445 个可走格） |
| 最常停留格占步数 | 中位 33.6%，最大 100% |
| 离开 ≥ 60 步后再回来的次数 | 中位 0，最大 7 |

## 3. 对 S2 结论的影响

- **仍然成立：**
  - 三臂长目标 0/50、训练后门未过、按登记停在 dev 之前，这些事实都不变；
  - 结案报告第 1 节「不对多时间尺度假设作任何结论」仍然成立；
  - dev、final 没有运行，长目标的 BFS 距离（从起点正向）是对的；
  - 诊断里的数值没有算错。
- **需要修正的读法：**
  - 结案报告第 4 节把失败归因于「隐空间 L2 代价地形不可用」和「臂 A 的规划接口」。这两个现象是在上述近乎静止的数据上训练的模型上测到的；
  - 数据缺陷是一个当时没有排除的混淆因素。现在不能确定代价地形问题在正常数据上是否仍然存在；
  - 第 8 节的重启条件只列了代价、臂 A 和冻结前实测，应当加上「先修数据生成器」。

## 4. 为什么没有被发现

- 现有测试和 smoke 检查的是确定性、段占比（非 BFS ≥ 50%）；没有测试断言 BFS 段真的能到达目标，也没有检查一回合的覆盖面。
- 规划端的 oracle 用的是真实动力学，不经过这个寻路函数。
- 段占比的门只数「这一段标记为 bfs」，不看这一段实际做了什么。

## 5. 处置

- 不改 S2 的代码和预登记（已收口、已冻结），不重跑登记运行。
- 建议做一次有界诊断（**须用户批准**）：同一批世界、同一批种子、同样 2757 步，只把寻路改成反向 BFS，每臂训练 1 个种子，重测结案报告第 8 节的三项指标（代价与 BFS 的秩相关、一步误差比、短目标成功率）。总上限 90 分钟。结果只作诊断，不构成登记结论，不改变 S2 已收口的状态。
- S3 不复用这个寻路函数（见 `reports/V9-S3-DESIGN/DESIGN-r0.md`）。

## 5a. 诊断结果（11-09 用户授权后运行，覆盖第 3 节的「需要修正的读法」）

只改寻路一处，世界布局逐个相同，每臂一个种子（42），2757 步。脚本、日志、结果在 `diagnostic/`，用时 3017 s，S2 账本和 `artifacts/v9/s2/phase1` 未被写入。

| 指标（臂 A / B / C） | 缺陷数据 | 修正寻路后 |
|---|---|---|
| 长目标成功率（50 条） | 0 / 0 / 0 | 0 / 0 / 0 |
| 短目标成功率（20 条） | 0 / 0 / 0.05 | 0 / 0 / 0.10 |
| 代价与 BFS 距离 Spearman | 0.286 / −0.087 / 0.127 | 0.256 / 0.038 / 0.101 |
| 一步误差 / 原地不动误差 | 2.785 / 0.036 / 0.299 | 2.112 / 0.032 / 0.310 |

| 数据（抽 500 回合） | 缺陷数据 | 修正寻路后 |
|---|---|---|
| WAIT 占环境步 | 40.7% | 17.3% |
| BFS 段内 WAIT | 60.6% | 4.9% |
| 一回合走过的不同格子（中位） | 14 | 32 |
| 最常停留格占比（中位） | 33.6% | 29.6% |

**结论：这个寻路缺陷是真的，但不是 S2 失败的主因。** 修好之后规划仍然失败，代价与真实距离的秩相关仍接近 0。结案报告第 4 节对代价地形和臂 A 接口的诊断在这次检验下仍然成立。第 3 节说的「未排除的混淆因素」，在本诊断范围内已经排除。

**限制：**
- 每臂只有一个种子。
- 只修了 BFS 段。登记要求 ≥ 50% 的非 BFS 段（惯性随机游走）没有改，一回合 32 个格子仍然偏窄（S3 的巡游生成器是 112）。所以结论是「修好这个缺陷本身不够」，不是「再好的数据也没用」。
- 规划代价和臂 A 接口都没有改。

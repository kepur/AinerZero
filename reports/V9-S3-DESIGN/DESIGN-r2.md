## 0. 这份设计要避开的错

| 过去的错 | 本设计的做法 |
|---|---|
| S2：协议冻结后才发现训练好的模型规划全 0 | §5 的探针必须用真训练模型，全过才登记预算 |
| S2：数据生成器寻路方向反了，没人发现（`addendum-data-defect`） | 生成器有硬性覆盖门，寻路有到达率测试 |
| S2、P198：把原地打转算作重访 | 只数「离开后再回来」，按间隔分桶 |
| E1：dev 反复使用，收益递减 | dev 至多用两次，final 冻结后才生成 |
| smoke 缺实测时回退写死的通过值 | 缺数据一律判失败，门读实测值 |
| 手工线索到天花板，比较无意义 | 探针要求手工线索在长间隔上处于登记窗口内 |

## 1. 问题与假设

只问一件事：**答案只存在于同一回合更早的经历里时，用什么记忆最好？**

- **H1（基础门）：** 外置非参数情景库配手工线索，长间隔读回准确率高于循环隐状态。这几乎由结构决定，只用来证明实验床和存储管线有效，不作为发现宣称。
- **H2（主假设，检索）：** 线索互相混淆时，学习检索高于手工线索。
- **H3（主假设，保护，式 6）：** 换一批世界继续训练后，旧世界族的读回不退化超过 ε。

**第一阶段不回答：** 跨回合记忆、巩固、FAST→MID→SLOW 晋升、Titans、Nested Learning，留给第二阶段。任何阳性都只说明这个任务上的结论，不宣称通用记忆能力，也不外推到规划。

## 2. 世界与任务：GridLab-S3

新包 `src/ainerzero/v9/experiments/s3/`。只读复用 S2 的 `make_layout`、`step`、`compute_ego_view`，不改 S2 的任何文件。寻路不复用 S2 的 `_find_path_step`。

**观察（允许观察，不含绝对坐标），共 198 维：**
- 3×3 视野（裁剪 `compute_ego_view` 的 7×7 中心）：每格地形 4 类 one-hot，加内容 token（两族合计 16 类，加「无」共 17 类）one-hot，共 9 × 21 = 189 维；
- 朝向 one-hot 4 维、上一动作 one-hot 4 维、是否撞墙 1 维。撞墙算自身本体感觉，属允许观察。`dt` 固定为 1。

**里程计与打滑：** 前进以概率 `p_slip = 0.05` 静默失败（不撞墙、不告知）。学生只能按「下了前进且没撞墙」累计位姿，所以位姿线索会漂移。正式成绩用估计位姿，真值位姿只作诊断上界。

**内容层：** 每回合 `M = 8` 个内容格，token 从所在世界族的 `C = 8` 类里取（F1 用 1–8，F2 用 9–16）。内容格位置、初始 token、换 token 的时刻和新 token 都逐回合独立随机，新 token 必须不同于旧 token。返回事件中约一半已经换过。

**行为策略（巡游）：** 反向多源 BFS 走向目标，10% 噪声。优先走到期的返回，否则去新目标，返回间隔按分桶抽取。回合长 T = 360。

**读回事件：** 回到内容格时提问「上次到这里时，这里是什么 token？」。「上次到这里」指智能体最近一次站在该格（包括路过），且中间离开过。读出头输出两族合计 16 类。

**一级实测**（`tier1-probe/`，16 个世界，T = 360，M = 8）：

| 指标 | S2 现有生成器 | 巡游原型 |
|---|---|---|
| 一回合走过的不同格子（中位） | 15.5 | 100.5 |
| 最常停留格占比（中位） | 33% | 3.6% |
| 每回合返回事件（中位） | — | 7.5–8.5 |

长间隔（≥ 80 步）返回时，手工线索取到正确地点的比例：

| 视野半径 | 打滑率 | 位姿 | 视野 | 两者结合（λ = 0.5） |
|---|---|---|---|---|
| 3 | 0.05 | 0.37 | 1.00 | 1.00 |
| 2 | 0.05 | 0.37 | 0.77 | 0.88 |
| **1** | **0.05** | **0.37** | **0.17** | **0.63** |
| 1 | 0 | 1.00 | 0.23 | 1.00 |

选半径 1、打滑 0.05：两条线索单独都不够，结合起来也远低于上限。这些是原型数字，§5 要在正式生成器上复测。

## 3. 臂

各臂共用同一个小编码器和读出头结构，参数量相差不超过 10%，同样的数据和更新次数。

| 臂 | 记忆 | 作用 |
|---|---|---|
| A0 | 无（零状态） | 地板，验证任务确实需要历史 |
| A1 | GRU 隐状态 | 循环结构基线 |
| A2 | 情景库 + 手工线索（权重在 train 上拟合后冻结） | H1、H2 的比较基准 |
| A3 | 情景库 + 学习检索 | H2 |
| O | 情景库 + 真值检索 | 上界，只作诊断 |
| N | A2，但库内容按回合内打乱 | 负对照，应掉到地板 |

- **情景库：** 每步写一条记录（估计位姿、时间、视野嵌入、观察到的 token）。写入不改网络参数。**回合结束时清空**，第一阶段不跨回合。
- **候选池：** 位姿前 4、视野前 4、两者结合前 4，合并去重，K ≤ 12。
- **学习检索（S3 读回效用）：** 对候选池里每条记录，用「带这条记录与不带时读回损失的差」作效用，训练打分头。编码器的梯度截断，防止检索和表示互相追逐。这是调研里 FAR「对未来的预测效用」的特化版本，只针对读回，报告里按此命名，不称作完整 FAR。

## 4. 指标与门

**主指标：** 长间隔（≥ 80 步）、token 已换过的事件的读回准确率。按回合配对 bootstrap 取 95% 区间。

无记忆模型在这类事件上的最优猜测是排除当前 token 后均匀猜，准确率 `chance = 1/(C−1) ≈ 0.143`。

下列门槛是**拟定值**，冻结前由 §5 探针校准，不按 dev 调整：

| 门 | 判据（拟定） |
|---|---|
| H1（基础门） | A2 − A1 ≥ 0.10，且配对 95% 区间下界 > 0 |
| H2 | A3 − A2 ≥ 0.05，且配对 95% 区间下界 > 0 |
| H3（式 6） | 换世界族后旧族读回下降 ≤ 0.05 |
| 合法性：地板 | A0 ≤ chance + 0.03 |
| 合法性：上界 | O ≥ 0.90 |
| 合法性：负对照 | N ≤ chance + 0.03 |
| 合法性：未换事件 | 被判阳性的臂，未换过事件的准确率 ≥ 0.80，防止「永远答一个和当前不同的」这类策略 |

合法性门任何一条不过，整个实验判无效，不解读 H1–H3。

**H3 的做法：** 先在世界族 F1 上训练 2000 步，再在 F2 上继续训练 1000 步。F2 换布局种子范围，并使用与 F1 不相交的 token 集，打滑率不变。不做「同一 token 换含义」，那是规则冲突，所有臂都必然下降，测不出保护能力。F2 阶段**编码器、读出头、打分头全部继续更新**，A2 的手工线索权重保持冻结。H3 测的是网络权重漂移造成的遗忘，不是存储本身（存储每回合清空）。

**常设报告，不进门：** M2 干扰诊断（`metrics.py` 的 `memory_interference`）、按间隔分桶的曲线、平衡准确率、检索的 precision@1 与候选池召回率、训练步耗时、峰值内存。

## 5. 冻结前探针（全过才登记预算）

| 探针 | 内容 | 过线 |
|---|---|---|
| P-a 数据 | 正式生成器、100 个世界 | 不同格子中位 ≥ 60；最常停留格占比最大 ≤ 0.15；≥ 90% 回合有长间隔已换 token 事件；已换比例 0.4–0.6 |
| P-b 寻路 | 反向 BFS | 无噪声到达率 100% |
| P-c 线索 | 手工线索 precision@1（长间隔） | 结合后在 0.50–0.75 之间 |
| P-c2 候选池 | 多路候选池召回率（长间隔） | ≥ 0.80 |
| P-d 上界 | O 短训 ≤ 500 步 | ≥ 0.90，否则任务或读出头有问题 |
| P-e 地板 | A0 短训 | ≤ chance + 0.03，否则有捷径 |
| P-f 负对照 | N 短训 | ≤ chance + 0.03 |
| P-g 成本 | 各臂实测步耗时（A3 单列） | 用于最终预算 |

P-d、P-e、P-f、P-g 需要短训练，总计上限 20 分钟，MLX CPU，一级登记。缺任何一项实测数据都判未通过。

**探针不过线时：** P-c、P-c2 可以只在 train 分区上调整打滑率和视野半径，每次调整都记录并重测。P-a、P-b、P-d、P-e、P-f 不过线，必须修实现或改设计，不能改过线值。dev 不参与任何调整。

## 6. 分区与用量

- train、dev、final 用互不重叠的登记种子命名空间（`s3p1-*`），世界布局和内容都不重叠。
- 规模（拟定）：train 400 世界 × 4 回合；dev 50 世界 × 2 回合；final 100 世界 × 2 回合。按原型的返回事件数估算，dev 约 250 个主指标事件，final 约 500 个。
- dev 至多使用两次，每次写明用途。
- final 在预登记冻结后才生成，只读一次，要有唯一批准行。

|---|---|
| 数据生成（train、dev、final、探针，纯 CPU） | 约 0.4 h |

## 9. 未决与风险

- **3×3 视野可能太难：** 编码器也许学不到有用的视野嵌入。P-d 过线前不继续。
- **容量受限对照（P201 建议）：** 暂不加，避免臂数膨胀。若 H1 阳性后想知道容量的影响，放第二阶段。
- **H2 可能阴性：** 手工线索在这个任务上可能已经够好。按登记如实报告，不换门槛。
- **S2 缺陷的波及面：** `_find_path_step` 只在 `s2/data.py` 使用。S1、E1 不经过它（P200 已核实）。
